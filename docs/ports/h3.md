commit recorded in the checkpoint (`fastvideo_commit 24bbe7fd...`,
`HF/fastvideo_inference.json`) is not publicly reachable, so FastVideo `main` is

**Which upstream is authoritative.** The checkpoint was trained and is served by
FastVideo. diffusers is a faithful port of the *base* model's math (same
weights, same packing, same scheduler) but knows nothing about this
checkpoint's three additions: the DMD rung ladder, VSA-H3 sparse attention, and
the `to_gate_compress` weights. Where they differ, FastVideo wins, and each
difference is called out below as **[D != F]**.

**Corrections to the brief this port was started from.** These were checked
against both upstreams and the checkpoint headers:

1. "Layer 50" is HF `hidden_states[50]`: index 0 is the embedding, so it is the
   residual stream **after decoder layer 49**, un-normed. Layers `0..=49` run;
   layer 50 does not. (section b)
2. There is **no chat template and no special-token wrapping**. The prompt is
   tokenized verbatim with `add_special_tokens=False`. `<d>` is dialogue markup
   *inside* prompts, not a template token. (section b)
3. The supported duration is **5 to 15 s** (124 to 362 frames), not 4 to 15. A
   4 s request aligns to 107 frames, which both upstreams reject. (section a)
4. The video VAE **decoder has no CNN**: it is a pure ViT plus one 1x1x1 conv.
   The CNN, GroupNorm and reflect padding are encoder-only, so T2AV needs none
   of them. (section c)
5. The packed sequence is **not padded to 64**. Only VSA's tile buffer is
   padded, per tile. (section a, e)
6. `to_gate_compress` is present **and trained** (nonzero), so the VSA
   compression branch is live at inference. (section e)
7. The on-disk transformer is **all BF16**, 70.10 GB, of which 26.02 GB is
   AdaLN. (section g)

## a. Inference contract

### Inputs

One prompt string, a seed, a canvas, a frame count. One request at a time
(`num_videos_per_prompt == 1`), no negative prompt, no CFG:
`guidance_scale` must be exactly `1.0` and a non-empty negative prompt is an
error (`F/st/input_preparation:47-60`). The checkpoint is guidance-distilled;
there is a single conditional forward per step.

This checkpoint supports **T2AV only**. FL2VA (keyframes) and Ref2VA were not
distilled (`HF/README.md`). Everything below assumes no keyframes and no
references, which removes every "condition row" code path.

### Canvas

`resolve_canvas_size(aw, ah)` (`F/pack:94-110`), float64 throughout:

```
ratio = aw / ah                      # must be in [1/4, 4]
(w, h) = (768*ratio, 768) if ratio >= 1 else (768, 768/ratio)
if w*h > 768*1344:  s = sqrt(768*1344 / (w*h));  w, h = w*s, h*s
H = max(32, round(h/32)*32);  W = max(32, round(w/32)*32)      # Python round: half to even
```

`16:9 -> H x W = 768 x 1344` (the unclamped 768 x 1365.33 exceeds the pixel cap,
scales to 761.98 x 1354.6, snaps to 768 x 1344). Other ratios: `9:16 -> 1344x768`,
`1:1 -> 768x768`, `4:3 -> 768x1024`, `21:9 -> 672x1536`. Explicit `height`/`width`
are accepted if both are positive multiples of 32 (`F/st/input_preparation:74-91`).

Latent grid: VAE spatial ratio 16, so `48 x 84` latents; DiT patch `(1,2,2)`, so
a **`24 x 42` token grid, 1008 video rows per latent frame**.

### Frames, fps, duration

Fixed 24 fps (`F/pack:21`, any other value is an error). `num_frames` is
aligned **up** to the next `17 n + 5` (`align_num_frames`, `F/pack:113-118`) and
the aligned value must lie in `[124, 362]`, i.e. 5 s to 15 s
(`F/pack:121-125`, `F/st/input_preparation:94-103`; diffusers says the same,
diffusers `docs/source/en/api/pipelines/minimax_h3.md:74`).

```
latent_frames = (num_frames - 5) / 17 * 5 + 2          # F/pack:128-131
```

| request | aligned frames | latent frames `T` | video rows `37.. * 1008` |
|---|---|---|---|
| 5 s (120) | 124 | 37 | 37 296 |
| 10 s (240) | 243 | 72 | 72 576 |
| 15 s (360) | 362 | 107 | 107 856 |

### Audio

32 kHz stereo. The audio VAE is mono at 40 latents/s (hop 800 samples); stereo
is **two independent latent streams through the same weights**, one per
channel (`D/avae:26-27`). Latents per channel:

```
audio_latents = round(num_frames / 24 * 40)            # F/pack:134-135, == num_frames * 5/3, never a tie
```

So `40` audio latents per second of video per channel, **80 audio rows per
second** in the packed sequence. 5 s: 207 per channel, 414 rows. 15 s: 603 per
channel, 1206 rows. Decoded length is exactly `800 * audio_latents` samples per
channel (165 600 for 5 s = 5.175 s, slightly longer than the 124/24 = 5.1667 s
of video; neither upstream trims, the muxer decides).

### Schedule

`HF/fastvideo_inference.json`: `num_inference_steps = 9` sigma-grid points,
`transformer_forwards = 8`, `dmd_denoising_steps = [999, 874, 749, 624, 500,
375, 250, 125]`, `video_scheduler_shift = 10.0`, `audio_scheduler_shift = 3.0`
(also `HF/scheduler/scheduler_config.json`, `HF/audio_scheduler/...`; the base
model uses 12/3). The pipeline refuses any other grid for this checkpoint
(`F/pipe:164-198`).

The 9-point grid is **not** `linspace(1, 0, 9)`. The rungs name *unshifted*
sigmas, and each modality shifts them independently
(`F/st/denoising:73-87`):

```
base      = float32([999, 874, 749, 624, 500, 375, 250, 125] / 1000.0 ++ [0.0])
sigma_m   = s_m * base / (1 + (s_m - 1) * base)        # float32 elementwise, s_video=10, s_audio=3
timestep_m = 1 - sigma_m[:-1]                          # float32; D/sched:165-168
```

The timestep fed to the transformer is `t = 1 - sigma in [0, 1]`, **`t = 1` is
clean**. The integers 999..125 never reach the model (`F/st/denoising:85-86`).

| i | rung | sigma_video | t_video | sigma_audio | t_audio |
|---|---|---|---|---|---|
| 0 | 999 | 0.99989986 | 0.00010014 | 0.99966639 | 0.00033361 |
| 1 | 874 | 0.98578835 | 0.01421165 | 0.95414841 | 0.04585159 |
| 2 | 749 | 0.96757525 | 0.03242475 | 0.89951956 | 0.10048044 |
| 3 | 624 | 0.94316810 | 0.05683190 | 0.83274013 | 0.16725987 |
| 4 | 500 | 0.90909094 | 0.09090906 | 0.75 | 0.25 |
| 5 | 375 | 0.85714287 | 0.14285713 | 0.64285713 | 0.35714287 |
| 6 | 250 | 0.76923078 | 0.23076922 | 0.5 | 0.5 |
| 7 | 125 | 0.58823532 | 0.41176468 | 0.30000001 | 0.69999999 |
| 8 | - | 0 | - | 0 | - |

Bit-exact float32 values are pinned in
`crates/fastvideo-models/src/h3/schedule.rs` tests.

**[D != F]** `MiniMaxH3Scheduler.set_timesteps(9)` builds the uniform grid
(`D/sched:155-159`), whose rungs 0..3 are `1.0, 0.875, 0.75, 0.625` rather than
`0.999, 0.874, 0.749, 0.624`. To reproduce FastH3 with diffusers, pass the
table above through `set_timesteps(sigmas=...)` (`D/sched:160-163`).

### Sparse attention

`vsa_sparsity = 0.8`, `vsa_tile_size = 64` tokens = a `(4,4,4)` tile, mode
"exempt" (`HF/fastvideo_inference.json`, `F/st/denoising:159-168`,
`F/vsa:85-94`). No dense-first-N-steps or dense-layer overrides are part of the
recipe (defaults `0` and `()`, `F/st/denoising:163-164`). Section e.

### Seed

`torch.Generator("cpu").manual_seed(seed)`, seed 0 if none is given
(`F/st/input_preparation:62-66`; the example script defaults to 1000). From that
one generator, in order (`F/st/latent_preparation:321-343`,
`D/mod/before_denoise:847-873`):

1. video noise, `randn([1, 24, T, 48, 84])` float32, then patchified;
2. audio noise drawn **directly in row layout**, `randn([2 * Na, 32])` float32.

Both are drawn on the CPU and copied to the device. torch's CPU normal sampler
is not reproducible from Rust without reimplementing it, so bit-parity with a
FastVideo run at a given seed is not a goal; the oracle saves its noise instead
(section j). Any `N(0,1)` source is a valid generator for users.

### Padding to 64

There is none at the sequence level. The original MiniMax reference pads the
packed sequence to a multiple of 64 and isolates the tail with `cu_seqlens =
[0, used, S]`; both ports dropped that (`D/dit:385-389`, `F/dit:570-575`
"padless"). What is 64-aligned is VSA's **tile buffer**: every tile owns 64
slots, a partial tile fills its first `size` slots and the rest stay zero, and a
per-tile size vector tells the kernel which slots are real (`F/vsa:216-263`,
`F/vsa:507-552`). FastVideo's optional sm_100a CUDA kernel additionally appends
one all-zero tile when the tile count is odd; that is a transport detail of
that kernel and has no semantic effect (`F/vsa:531-552`, `F/vsa:659-668`).

## b. Text encoder

### Model

`Qwen3VLForConditionalGeneration` (Qwen3-VL-32B), `HF/text_encoder/config.json`
`text_config`: hidden 5120, 64 layers, 64 query heads, **8 KV heads** (GQA,
group 8), head_dim 128 (so Q is 8192 wide, K/V 1024 wide, not `hidden/heads`),
SwiGLU intermediate 25600, RMSNorm eps 1e-6, `rope_theta 5e6`,
`mrope_section [24,20,20]` interleaved, no attention bias, vocab 151 936, BF16
on disk. The vision tower and `lm_head` are never used for T2AV.

### Which hidden state

Both upstreams read **HF `hidden_states[50]`**:
`outputs.hidden_states[text_encoder_layer]` with `text_encoder_layer = 50`
(`D/mod/encoders:35,99`); FastVideo returns from the layer loop when
`layer_index + 1 == output_hidden_state_index` with the index `50`
(`F/qwen:326-337`, `F/qwencfg:65`), and builds only 50 layers
(`num_hidden_layers_override = 50`, `F/qwencfg:66`, `F/qwen:303-311`).

`hidden_states[0]` is the embedding output, `hidden_states[i]` the residual
stream after decoder layer `i-1`. Therefore:

* run decoder layers **0 through 49** (50 layers);
* take the residual stream as is: **no final `norm`**. diffusers guards this
  explicitly: a stack truncated to exactly 50 layers would return a post-norm
  state, "not the conditioning MiniMax-H3 expects" (`D/mod/encoders:63-70`);
* layers 50..63, `model.language_model.norm`, `lm_head`, `model.visual.*` are
  never read.

Output: `[1, N, 5120]`, BF16 in both upstreams, one row per prompt token,
unpadded.

**In `fastvideo_cudarc::llm` terms: tap `k = 50`.** `llm::hidden_states` uses
the HF `output_hidden_states` numbering (tap 0 = embeddings, tap `k` = the
stream after `k` decoder layers, tap 64 = the only normed entry), so
`taps = [50]` runs layers 0..49, reads nothing past them, and skips the final
norm, which is exactly the contract above. "The 50th layer" of the model card
is the 50th layer counting from one, zero-based index 49. Proof lines:
`D/mod/encoders:99` (`outputs.hidden_states[text_encoder_layer]`, default 50 at
`:35`), `F/qwen:335` (`if layer_index + 1 == self.output_hidden_state_index:
return hidden_states`, inside `enumerate(self.layers)`) with `F/qwencfg:65`
(`output_hidden_state_index: int = 50`), and `F/pack:31`
(`MINIMAX_H3_TEXT_ENCODER_LAYER = 50`).

`DecoderConfig::qwen3_vl_32b_text()` was checked field by field against
`HF/text_encoder/config.json` and the safetensors headers and is **correct as
written**: hidden 5120, 64 heads, 8 KV heads, head_dim 128, intermediate 25600,
eps 1e-6, SiLU gate, per-head q/k norm, embed scale 1, 64 layers all with theta
5e6 / factor 1 / no window (`rope_type: default`, no sliding window in the
config). Key names confirmed in the headers: `model.language_model.layers.N.`
`{input_layernorm,post_attention_layernorm}.weight [5120]`,
`self_attn.{q_proj [8192,5120], k_proj [1024,5120], v_proj [1024,5120], o_proj
[5120,8192]}.weight`, `self_attn.{q_norm,k_norm}.weight [128]`,
`mlp.{gate_proj,up_proj [25600,5120], down_proj [5120,25600]}.weight`;
`model.language_model.embed_tokens.weight [151936,5120]`;
`model.language_model.norm.weight [5120]`. There are no bias tensors. One
immaterial numeric difference: `llm::rope_tables` forms angles in float64,
while the reference forms `inv_freq` and the angles in float32 and then casts
cos/sin to **bf16** (`F/qwen:105,116-124`); the reference's own bf16 rounding
of the tables (~3 significant digits) is orders of magnitude larger than the
f32/f64 gap, so no change is needed.

### Tokenization and prompt format

`Qwen2TokenizerFast`, byte-level BPE, NFC normalizer, the Qwen2 split regex, no
BOS (`HF/tokenizer/tokenizer.json`, `tokenizer_config.json`). The `tokenizers`
crate already in `fastvideo-models` loads `tokenizer.json` directly.

```
token_ids = tokenizer(prompt, add_special_tokens=False)["input_ids"]
```

(`D/mod/encoders:192`, `F/st/conditioning:187`, `F/qwencfg:149-151`). **The
prompt is encoded verbatim: no chat template, no system prompt, no
`<|im_start|>`, no BOS/EOS, no padding.** `HF/processor/chat_template.json`
exists in the repo and is unused. The only structured prefix either upstream
ever emits is `"<Picture i>: "` + a vision block per keyframe, which T2AV does
not have (`F/st/conditioning:170-185`).

Max length: **neither inference path truncates or pads**. FastVideo's config
carries `text_len = 1024` with the comment "H3 text conditioning truncates at
1,024 tokens" (`F/qwencfg:70-72`), but that field is consumed by the training
data loader, not by the conditioning stage. Recommendation: reject prompts over
1024 tokens rather than silently truncating.

Attention mask: a single unpadded sequence, so the mask is all ones and
FastVideo drops it (`F/qwen:322-323`); attention is plain **causal**
(`is_causal = seq > 1`, `F/qwen:198-207`). Qwen3-VL is a causal LM, so the
conditioning is causal-attention hidden states, not bidirectional ones.

**Special tokens (`<d>` etc.).** `tokenizer_config.json` lists seven
`additional_special_tokens` that `tokenizer.json` does *not* define: `<d>`,
`</d>`, `<|cutoff|>`, `<|lyrics_start|>`, `<|lyrics_end|>`,
`<|caption_start|>`, `<|caption_end|>`. transformers appends such tokens to the
vocabulary when it loads a fast tokenizer. The base model card says "We add
several special tokens, such as `<d>`, to the tokenizer configuration"
(`MiniMaxAI/MiniMax-H3 README:120`), and its example prompts wrap spoken lines
as `<d>[English] Follow the wind, live free.</d>`. `tokenizer.json` ends at id
151668 (`</think>`), so the expected ids are 151669..151675 in the listed
order, inside the 151 936-row embedding table. **Verified on hardware**
(transformers 5.17, RTX PRO 6000 run of `h3 text`): `<d>` = 151669, `</d>` =
151670, `<|cutoff|>` = 151671, `<|lyrics_start|>` = 151672, `<|lyrics_end|>` =
151673, `<|caption_start|>` = 151674, `<|caption_end|>` = 151675, and a
35-token prompt tokenizes identically on both sides. The markers are *not* in
`tokenizer_config.json`'s `added_tokens_decoder`, only in
`additional_special_tokens`, so their ids come from append order; the Rust
tokenizer (`fastvideo_models::h3::tokenizer`) appends the same seven strings in
the same order, and `h3_oracle.py` registers them itself on a transformers
release that does not.

### mRoPE for pure text

`_get_rope_index` with no vision inputs and no mask returns
`arange(N)` for all three axes (`F/qwen:584-587`). The interleaved mRoPE starts
from the temporal frequencies and overwrites indices `1,4,7,..` (up to `3*20`)
with the height axis and `2,5,8,..` with the width axis
(`F/qwen:116-121`). With all three axes equal the overwrite is the identity, so
**for text-only input mRoPE is ordinary 1-D RoPE over all 128 channels**:

```
inv_freq[i] = 5e6 ** (-(2i)/128),  i = 0..63                    # float32, F/qwen:105
ang[p, i]   = p * inv_freq[i]                                    # float32, autocast disabled
cos = cos(cat(ang, ang)),  sin = sin(cat(ang, ang))              # [N, 128], then cast to bf16
rotate_half(x) = cat(-x[..., 64:], x[..., :64])
q' = q * cos + rotate_half(q) * sin                              # same for k; F/qwen:26-28,192-196
```

i.e. channel `j < 64` pairs with channel `j + 64` (the HF Llama convention, not
interleaved pairs).

### One decoder layer (`F/qwen:178-289`)

```
h = x
x = RMSNorm(h; input_layernorm, eps 1e-6)
q = q_proj(x).view(N, 64, 128);  k = k_proj(x).view(N, 8, 128);  v = v_proj(x).view(N, 8, 128)
q = RMSNorm_per_head(q; q_norm[128], eps 1e-6);  k = RMSNorm_per_head(k; k_norm[128])   # over the last 128 only
q, k = rope(q), rope(k)
k, v = repeat each of the 8 KV heads 8 times consecutively          # query head h uses KV head h // 8
a = softmax(q k^T / sqrt(128) + causal) v  ->  [N, 8192]
h = h + o_proj(a)
x = RMSNorm(h; post_attention_layernorm)
h = h + down_proj(silu(gate_proj(x)) * up_proj(x))                   # gate FIRST here, unlike the DiT
```

RMSNorm is `x * rsqrt(mean(x^2) + eps) * weight` (no `1 +`). Embedding lookup:
`embed_tokens[token_id]`, no scaling.

### What the DiT does with it (`F/dit:857-880`, `D/dit:628-631`)

```
e = context_embedder(text)                      # Linear 5120 -> 5376, bias, bf16
for block in token_refiner.refiner_blocks (2):  # plain pre-norm, NO AdaLN, NO RoPE, full bidirectional attention
    e = e + attn(RMSNorm(e; norm1, 1e-5))       # same attention module as the DiT blocks: 56 x 128, per-head QK norm
    e = e + ff(RMSNorm(e; norm2, 1e-5))         # SwiGLU 5376 -> 2*14336 -> 5376, value half first
e = RMSNorm(e; token_refiner.final_norm, 1e-5)  # [1, N, 5376]
```

This is timestep-free, so it runs **once per generation** and its 1.60 GB of
weights can be released afterwards (`F/dit:857-880` caches it the same way).
The refiner never uses VSA (`F/dit:700-704`).

## c. Video VAE (`AutoencoderKLMiniMaxH3`, f16t4d24): decoder only

T2AV never encodes video. The needed weights are `decoder.*` and
`post_quant_conv.*`: 585 tensors, 9 694 124 384 bytes, F32.

### Latent normalization

DiT-space latents are normalized. Before decoding (`D/mod/decoders:183-185`,
`F/vvae:641-642`):

```
z[:, c] = latent[:, c] * latents_std[c] + latents_mean[c]          # 24 channels, values in HF/vae/config.json
```

Both arrays are in `H3VideoVaeConfig`.

### Decoder architecture (`D/vae:398-498`)

The decoder is a **non-causal ViT**; there is no convolutional upsampling path.
For one call on `z: [1, 24, T, H, W]` (in practice `T = 7`, `H = W = 16`, see
chunking below):

```
x = post_quant_conv(z)                          # Conv3d 24 -> 24, kernel 1: a per-voxel Linear(24, 24) + bias
x = x.permute(0,2,3,4,1).reshape(1, T*H*W, 24)  # token order: t, then h, then w (row-major)
x = proj_in(x)                                  # Linear 24 -> 2048, bias
x = cat([x, register_tokens(4 x 2048, learned), zeros(1 x 2048)], dim=1)   # 5 extra tokens APPENDED; the last is all-zero, not learned
for 36 blocks:
    n = RMSNorm(x.float(); norm1 weight, eps 1e-5)             # norms run in float32
    x = x + attn(n) * scale1                                   # scale1: [2048] LayerScale
    n = RMSNorm(x.float(); norm2 weight, eps 1e-5)
    x = x + ff(n) * scale2
x = LayerNorm(x; norm_out weight+bias, eps 1e-5)
x = proj_out(x)                                 # Linear 2048 -> 3072 = 3 * 4 * 16 * 16, bias
x = x[:, :T*H*W]                                # drop the 5 extra tokens
x = x.view(1, T, H, W, 3, 4, 16, 16).permute(0,4,1,5,2,6,3,7).reshape(1, 3, 4T, 16H, 16W)
```

So within the 3072-vector the layout is `[channel(3), dt(4), dy(16), dx(16)]`,
channel-major.

Attention (`D/vae:299-340`): 32 heads x 64, `to_q/to_k/to_v/to_out.0` all
`Linear(2048, 2048)` **with bias**; per-head RMSNorm on q and k over the 64
channels with **no learned weight** (`elementwise_affine=False`), eps 1e-5,
computed in float32; partial rotate-half RoPE; full (unmasked) softmax
attention, scale `1/sqrt(64)`, over `T*H*W + 5` tokens.

FFN: `ff.net.0.proj: Linear(2048, 16384)` with bias, split into
`(value, gate) = chunk(2)`, `value * silu(gate)`, then `ff.net.2: Linear(8192,
2048)` with bias (`decoder_ffn_mult = 4`).

RoPE (`D/vae:279-296`, `D/vae:460-468`): rotary width `int(64 * 0.75) = 48`
channels per head, 3 axes x 8 frequencies.

```
inv_freq[k] = 100 ** (-k/8),  k = 0..7                         # theta = 100, arange(0, 1, 6/48)
pos_axis[i] = 2 * ((i + 0.5) / size_axis) - 1                  # length-normalized to (-1, 1), per call
ang = 2*pi * pos[:, axis, None] * inv_freq                     # [tokens, 3, 8] -> flatten -> [tokens, 24]
cos/sin = cos/sin(cat(ang, ang))                               # [tokens, 48]: (t8, h8, w8, t8, h8, w8)
```

rotate-half over the first 48 channels (channel `j < 24` pairs with `j + 24`),
channels 48..63 pass through. The 5 extra tokens sit at position `(0,0,0)`,
i.e. angle 0, i.e. unrotated. Note the positions are normalized by the size of
**the tensor passed to that call**, so they depend on the tile/chunk geometry.

### Temporal chunking: `clip_length 17`, `token_drop 3`

Derived constants (`D/vae:593-599`): `frame_pre_padding = (-17) % 4 = 3`,
`tokens_chunk_size = ceil(17/4) = 5`, `token_overlap = (-3) % 5 = 2`,
`frame_overlap = max(2*4 - 3, 0) = 5`.

Meaning: the encoder consumed 17-frame clips, each producing 5 latent frames,
and dropped the last 3 latents of the whole video, which is why `17n + 5`
frames give `5n + 2` latents. The decoder mirrors that (`D/vae:793-842`,
streaming form `F/vvae:890-952`). For `T = 5n + 2` latents there is no padding
and exactly `n` decoder chunks:

```
for i in 0..n:
    clip = decode_clip(z[:, :, 5i : 5i + 7])        # 7 latent frames -> 28 pixel frames
    body = clip[:, :, 3:20]                         # 17 frames (drop the 3 pre-padding frames)
    if i > 0: body[:, :, :5] = lerp(tail_prev, body[:, :, :5])   # weights (1 - j/5, j/5), j = 0..4
    emit body
    tail_prev = clip[:, :, 23:28]                   # 5 frames: second 20-frame window, minus its 3 pre-padding frames
emit tail_prev                                       # the final 5 frames
```

Output frames `= 17 n + 5` = the aligned `num_frames` exactly (124 for 37
latents, 362 for 107). The general form with padding for other `T` is
`H3VideoVaeConfig::temporal_decode_plan`. `_blend` weights are `a * (1 - j/E) +
b * (j/E)` for `j = 0..E-1` (`D/vae:668-686`): the first blended frame is
entirely the previous chunk.

### Spatial tiling (on by default, part of the released output)

"MiniMax-H3 was released with tiling enabled ... the released frames are the
blended-tile ones, so disabling tiling changes the output" (`D/vae:520-523`).
Tile 256 px (16 latents), minimum overlap 64 px (`D/vae:608-615`).
`_split_tiles` (`D/vae:645-666`) picks the fewest tiles whose union covers the
axis with every overlap >= 64, then hands the slack back to the overlaps
round-robin in 16 px steps:

| axis | tiles | starts (px) | overlaps (px) |
|---|---|---|---|
| 768 | 4 | 0, 160, 336, 512 | 96, 80, 80 |
| 1344 | 7 | 0, 176, 352, 528, 704, 896, 1088 | 80, 80, 80, 80, 64, 64 |

Each tile is decoded independently (its own RoPE positions), then stitched
(`D/vae:688-708`): tile `(i,j)` is first blended with the tile above over
`overlap_h[i-1]` rows, then with the tile to its left over `overlap_w[j-1]`
columns (same linear ramp, in pixel space), then cropped by its own trailing
overlap, and the crops are concatenated. Order matters: vertical blend, then
horizontal. Both blends read the **raw decoded neighbour** (`tiles[i-1][j]` and
`row[j-1]` index the input lists, which `_stitch_tiles` never mutates; FastVideo
`F/vvae:733-752` is identical), so in a corner region the left neighbour enters
without its own vertical blend. (An earlier revision of this document said
"already blended"; the code says otherwise and the port follows the code.)

So one ViT forward sees `7 * 16 * 16 + 5 = 1797` tokens. A 5 s clip is `7
chunks x 28 tiles = 196` forwards; 15 s is `21 x 28 = 588`.

### Precision and pixel space

Weights are F32 and pinned F32 (`D/vae:529-532`). The shipped recipe decodes
under **float16 autocast over float32 weights** (`D/mod/decoders:187-188`,
`F/st/decoding:145-148`): matmuls in fp16, the RMSNorm/QK-norm lines above in
float32. The oracle records the fp16-vs-fp32 gap so the port can run the
decoder in float32 (or bf16 inside Linear) against a known budget.

Output is ImageNet-normalized RGB. Post-process (`D/mod/decoders:189-191`,
`F/vvae:1009`): `rgb = clamp(out * [0.229, 0.224, 0.225] + [0.485, 0.456,
0.406], 0, 1)`.

### Memory per chunk

Activations are small: tokens `1797 x 2048` f32 = 14.7 MB; the widest tensor is
the FFN's `1797 x 16384` = 118 MB; attention scores `32 x 1797^2` f32 = 413 MB
if materialized (flash at d=64 avoids it). One decoded tile is `3 x 28 x 256 x
256` f32 = 22 MB, the 28 tiles of a chunk 617 MB, the stitched chunk `3 x 28 x
768 x 1344` = 347 MB. **About 1.5 GB of working set per chunk**, independent of
clip length if frames are streamed to the host per chunk as FastVideo does
(`F/vvae:997-1011`). Weights dominate: 9.69 GB F32, or 4.85 GB as bf16 Linear.

## d. Audio VAE (`AutoencoderKLMiniMaxH3Audio`): decoder only

Needed: `dec_in_proj.*` and `decoder.*`, 914 tensors, 259 757 412 bytes, F32.
Must stay float32: "degrades audibly under bfloat16 (roughly 20 dB quieter
decodes)" (`D/avae:531-534`).

### Latents and stereo

DiT audio rows are `[2 * Na, 32]`, **channel-major**: rows `0..Na` are the left
channel's latents in time order, rows `Na..2Na` the right's. Unpack
(`F/pack:194-196`): `rows.reshape(2, Na, 32).permute(0, 2, 1) -> [2, 32, Na]`,
i.e. a batch of two mono latents. Denormalize per channel
(`D/mod/decoders:243-245`): `z[:, c] = lat[:, c] * latents_std[c] +
latents_mean[c]` (32 values each, in `H3AudioVaeConfig`). Decode gives `[2, 1,
800 Na]`; the waveform is `decoded[:, 0].T -> [samples, 2]`
(`F/st/decoding:215-219`). Same weights for both channels; no cross-channel op.

### Decoder (`D/avae:426-486`, BigVGAN v2 style)

All convs marked `wn` are weight-normalized on disk as `weight_g`, `weight_v`:
`weight = weight_g * weight_v / ||weight_v||`, the norm taken over every dim
except dim 0. For `Conv1d` dim 0 is `out` (`weight_g: [out,1,1]`); for
`ConvTranspose1d` dim 0 is **`in`** (`weight_g: [in,1,1]`, confirmed in the
checkpoint header: `decoder.ups.0.0.weight_g [1024,1,1]` with `weight_v
[1024,512,9]`). Fold once at load time.

```
x = dec_in_proj(z)                           # Conv1d 32 -> 2048, k=1, bias (not weight-normed)
x = conv_pre(x)                              # wn Conv1d 2048 -> 1024, k=7, pad 3, bias
for i in 0..7:                               # rates (5,5,2,2,2,2,2), kernels (9,9,4,4,4,4,4)
    x = ups[i][0](x)                         # wn ConvTranspose1d C_i -> C_i/2, kernel k_i, stride r_i, padding (k_i - r_i)/2, bias
    x = (amp[3i](x) + amp[3i+1](x) + amp[3i+2](x)) / 3      # AMP blocks with kernels 3, 7, 11, all on the SAME input
x = activation_post(x)                       # alias-free SnakeBeta, 8 channels
x = conv_post(x)                             # wn Conv1d 8 -> 1, k=7, pad 3, NO bias
x = clamp(x, -1, 1)
```

Channels: `1024 -> 512 -> 256 -> 128 -> 64 -> 32 -> 16 -> 8`. Transposed-conv
output length `(L-1)*r - 2*pad + k` equals `L * r` at every stage (`5L` for
`k=9, r=5, pad=2`; `2L` for `k=4, r=2, pad=1`), so the chain is `Na -> 5Na ->
25Na -> 50 -> 100 -> 200 -> 400 -> 800 Na` and **output length = 800 * Na**
exactly. No `output_padding`, no dilation.

AMP block (`D/avae:389-423`), kernel `K in {3,7,11}`, dilations `(1,3,5)`:

```
for d, (c1, c2, a1, a2) in zip((1,3,5), ...):      # activations[0::2] feed convs1, activations[1::2] feed convs2
    r = c1(a1(x))          # wn Conv1d C -> C, kernel K, dilation d, padding d*(K-1)/2, bias
    r = c2(a2(r))          # wn Conv1d C -> C, kernel K, dilation 1, padding (K-1)/2, bias
    x = x + r
```

Alias-free activation `Activation1d` (`D/avae:170-219`), identical everywhere
(ratio 2, 12-tap Kaiser-sinc filter stored in the checkpoint as `filter`
buffers, `[1,1,12]`, all equal; load one, do not recompute):

```
up:   x = replicate_pad(x, 5, 5)
      x = 2 * conv_transpose1d(x, filter per channel (depthwise, groups = C), stride 2)
      x = x[..., 15:-15]                           # length 2L
act:  x = x + 1/(exp(beta_c) + 1e-9) * sin(exp(alpha_c) * x)^2      # SnakeBeta: alpha, beta are [C], stored in LOG space
down: x = replicate_pad(x, 5, 6)
      x = conv1d(x, filter per channel (depthwise), stride 2)       # length L
```

The decoder has **no attention** and no plain Snake: `num_attention_heads = 8`
and `MiniMaxH3AudioSnake1d` (`alpha` stored linearly, shape `[1,C,1]`) belong to
the encoder and its `pre_block`, which T2AV never runs.

Working set: the largest activation is `C_i * L_i = 6400 * Na` elements (every
stage from the second on), doubled inside an activation. At 15 s (`Na = 603`),
two channels: `2 * 2 * 6400 * 603 * 4 B = 62 MB`. No chunking needed.

## e. The DiT (`MiniMaxH3Transformer3DModel`)

One stack of 50 identical blocks over **one packed 1-D sequence**, full
self-attention, no cross-attention, no per-modality block weights. Modality
enters through two input projections, the per-row AdaLN table, and two output
heads (`D/dit:376-394`). Hidden 5376, 56 heads x 128 = **7168 (wider than the
residual)**, FFN 14336, `time_embed_dim` 2688.

### Packed layout for T2AV (`F/pack:227-298`, identical to `D/mod/before_denoise:268-372`)

```
[ text rows (N) | audio rows (2 Na) | video rows (T * 24 * 42) ]
```

(Keyframe condition rows would sit between text and audio; T2AV has none.)

| rows | count | `token_tag` | timestep | position `(t, h, w)` float64 |
|---|---|---|---|---|
| text `i` | N | 1 | **video** timestep | `(i, 0, 0)` |
| audio L, latent `a` | Na | 2 | audio timestep | `(N + a, 0, wgrid[0])` |
| audio R, latent `a` | Na | 2 | audio timestep | `(N + a, 0, wgrid[last])` |
| video `(f, y, x)` | T*24*42 | 0 | video timestep | `(N + tgrid[f], hgrid[y], wgrid[x])` |

Video rows are ordered frame-major, then row-major (`f`, then `y`, then `x`).

Spatial grids (`F/pack:199-204`, `F/pack:308-318`), numpy float64 with
`endpoint=False` (i.e. `start + k * (stop - start) / num`):

```
A = sqrt(latent_h * latent_w)                          # sqrt(48*84) = 63.49803146555018
grid(dim, patch): r = dim / A;  left = (1 - r) / 2
                  32 * (left + k * r / (dim/patch)),  k = 0 .. dim/patch - 1
```

At 48x84: `hgrid` = 24 values from 3.9051368637047297 in steps of 1.00790526...
to 27.08695787493733; `wgrid` = 42 values from -5.166010488516722 to
36.15810522715877, same step. A square canvas would span `[0, 32)`.

Temporal grid (`F/pack:207-216`): latent frame spans are `5/3 * (1, 4, 4, 4, 4)`
repeating, and `tgrid[f]` is the cumulative sum of the spans before `f`:
`0, 1.6667, 8.3333, 15, 21.6667, 28.3333, 30, ...` (`tgrid[36] = 200`). One unit
is 1/40 s (24 fps x 5/3), which is exactly one audio latent, so audio latent `a`
and the video frame at time `a/40` s share a rotary time. The first latent of
each 5-latent chunk covers 1 pixel frame, the other four cover 4.

`position_ids` are built in float64 and cast to float32 inside the rope
(`F/dit:85`). `timestep_indices` (`F/pack:489-500`): fill every row with the
video timestep, overwrite the audio rows with the audio timestep, then
`unique(sorted=True, return_inverse=True)`. With shifts 10 and 3, `t_video <
t_audio` at every rung, so `timestep = [t_video, t_audio]`, video and text rows
get index 0, audio rows index 1.

### Patchify (`F/pack:151-168`)

```
lat [1, 24, T, 48, 84] -> reshape [1, 24, T, 1, 24, 2, 42, 2]
                       -> permute (0, 2, 4, 6, 1, 3, 5, 7)  -> reshape [T*24*42, 96]
```

Row features are **channel-major**: `feature[c*4 + dy*2 + dx] = lat[c, f, 2y+dy,
2x+dx]`. "do not use einops's common patch-major order" (`F/pack:166`).
Unpatchify is the inverse (`F/pack:171-191`): `reshape(1, T, 24, 42, 24, 1, 2,
2).permute(0, 4, 1, 5, 2, 6, 3, 7).reshape(1, 24, T, 48, 84)`.

### Embedding and precision split

```
video_embeds = proj_in(video_rows)             # Linear 96 -> 5376, bias, float32
audio_embeds = audio_proj_in(audio_rows)       # Linear 32 -> 5376, bias, float32
text_embeds  = refined text (section b)        # bf16; sets the dtype of the packed buffer
packed[text_idx] = text;  packed[video_idx] = bf16(video);  packed[audio_idx] = bf16(audio)
```

`proj_in`, `audio_proj_in`, `time_embedder`, `proj_out`, `audio_proj_out` and
the rope buffer compute in float32; the block stack, `context_embedder`,
refiner, AdaLN projections and `norm_out` in bf16 (`F/dit:583-607`,
`D/dit:440-451`). On disk everything is BF16 in this export, so the float32
modules hold bf16-valued weights upcast.

### Time embedding (`F/dit:922-923`, `visual_embedding.py:208-256`)

Input is the *unscaled* `t in [0,1]`, one row per distinct timestep (2 rows):

```
f_k  = exp(-ln(10000) * k / 128),  k = 0..127            # float32; downscale_freq_shift = 0
emb  = cat(cos(t * f_k), sin(t * f_k))                   # [256], cos FIRST (flip_sin_to_cos)
temb = linear_2(silu(linear_1(emb)))                     # 256 -> 5376 -> 2688, both with bias, float32
```

### AdaLN and its precompute

Each block owns `adaln_proj.linear: Linear(2688, 96768)` with bias, 520 MB in
bf16, 26.02 GB across the stack. It is a function of the timestep only
(`F/dit:421-425`, `D/dit:124-131`):

```
y = adaln_proj.linear(bf16(silu(temb)))                  # silu in float32, THEN cast; [n_t, 96768]
y = y.view(n_t * 3, 6 * 5376)                            # row = timestep_index * 3 + tag
shift_msa, scale_msa, gate_msa, shift_mlp, scale_mlp, gate_mlp = y.chunk(6, dim=-1)
```

So within one timestep's 96768 outputs, modality `m` (0 video, 1 text, 2 audio)
owns `[m*32256, (m+1)*32256)`, and parameter `p` of it owns the 5376-wide slice
`[m*32256 + p*5376, ...)` in the order above. Rows select by `adaln_index =
timestep_index * 3 + token_tag` (`F/dit:926`).

**Which combinations a T2AV run touches.** Per step only three of the six
`(timestep, modality)` rows: `(t_video, video) = 0`, `(t_video, text) = 1`,
`(t_audio, audio) = 5`. Over the ladder: `8 steps x 3 rows x 50 blocks x 6 x
5376` values. The ladder is a constant of the checkpoint, so **the whole table
is a constant of the checkpoint**:

```
table_blocks : [8, 50, 3, 6, 5376]   float32 = 154.8 MB   (77.4 MB as bf16)
table_out    : [8, 2, 2, 5376]       float32 =   0.7 MB   (norm_out shift, scale; per timestep, not per modality)
```

Precompute procedure, once per checkpoint, cached on disk keyed by
`checkpoint_content_sha256` + ladder + both shifts:

1. Build `t_video[0..8]`, `t_audio[0..8]` (section a). Compute the 16 `temb`
   vectors in float32 with the (upcast) `time_embedder` weights; keep
   `s = silu(temb)`.
2. For each block `b`, stream `adaln_proj.linear.{weight,bias}` from its shard
   (one 520 MB tensor at a time; never resident). Only two row ranges are
   needed: rows `[0, 64512)` against the 8 `s(t_video)` vectors (video + text)
   and rows `[64512, 96768)` against the 8 `s(t_audio)` vectors (audio). That is
   `8 * 96768 * 2688 = 2.1 G` multiply-adds per block: host float32 is fine, or
   a transient bf16 GEMM on the device to stay closest to the reference.
3. Same for `norm_out.linear` (`[10752, 2688]`): `shift = out[:5376]`, `scale =
   out[5376:]` (`F/dit:459-462`), for each of the 16 timesteps.
4. At run time, step `i` uploads (or indexes) `table_blocks[i]` and the row ->
   slot map `{video rows: 0, text rows: 1, audio rows: 2}`; this is exactly the
   backend's existing "adaLN modulation from a per-slot table", with 3 slots.

After this, `adaln_proj.*`, `norm_out.linear.*` and `time_embedder.*` are never
loaded to the device: 26 110 409 472 bytes saved.

A generic (non-ladder) request would need the projections; that is out of scope
for this checkpoint, whose pipeline rejects any other grid.

### Block math (`F/dit:516-566`)

`a = adaln_index` per row; all modulation tensors cast to the stream dtype.

```
n = RMSNorm(x; norm1, 1e-5) * (1 + scale_msa[a]) + shift_msa[a]
x = x + gate_msa[a] * attn(n)
n = RMSNorm(x; norm2, 1e-5) * (1 + scale_mlp[a]) + shift_mlp[a]
x = x + gate_mlp[a] * ff(n)
```

No tanh or other squashing on the gates. RMSNorm has a learned weight `[5376]`.

Attention (`F/dit:276-318`):

```
q, k, v = to_q(n), to_k(n), to_v(n)                 # Linear 5376 -> 7168, NO bias
q, k, v -> [1, S, 56, 128]
q = RMSNorm(q; norm_q[128], 1e-5);  k = RMSNorm(k; norm_k[128], 1e-5)     # PER HEAD, over the last 128, shared weight across heads
q, k = rope(q), rope(k)
g = to_gate_compress(n) -> [1, S, 56, 128]          # Linear 5376 -> 7168, no bias; NOT normed, NOT rotated; VSA only
o = attention(q, k, v, g)                           # dense softmax, or VSA-H3 below; scale 1/sqrt(128); bidirectional
x_attn = to_out(o.flatten(2, 3))                    # Linear 7168 -> 5376, no bias  (key: attn.to_out.0.weight)
```

QK norm is verified per-head: `nn.RMSNorm(attention_head_dim)` applied after
`unflatten(-1, (heads, head_dim))` (`F/dit:181-182,285-296`, `D/dit:182-187`),
and the checkpoint tensors are `[128]`. The backend's existing fused QK-norm
over `heads * head_dim` is the wrong op here.

MM-RoPE (`F/dit:74-93`, `F/dit:259-274`), `rope_freq_dim = 16`, theta 1e4:

```
inv_freq[k] = 10000 ** (-k/16),  k = 0..15          # ONE buffer shared by the three axes; float32
ang_axis    = pos_axis * inv_freq                   # [S, 16] each, float32
A           = cat(ang_t, ang_h, ang_w)              # [S, 48]
cos, sin    = cos(cat(A, A)), sin(cat(A, A))        # [S, 96], cast to the stream dtype (bf16 upstream)
x_rot = x[..., :96];  x_pass = x[..., 96:]
x1, x2 = x_rot[..., :48], x_rot[..., 48:]
out = cat(x_rot * cos + cat(-x2, x1) * sin, x_pass)
```

**This is exactly `CudaTensor::rope_half` with `R = 96`**: rotated channels are
the contiguous prefix `[0, 96)` of each 128-wide head, in rotate-half
convention (pair `j` with `j + R/2 = j + 48`), with caller-supplied `[S, 96]`
tables laid out `cat(A, A)`, `A = [t x16 | h x16 | w x16]`. No other channel
set or ordering is involved, and q and k use the same tables. The same op
serves the VAE decoder with `R = 48` of 64 (`A = [t x8 | h x8 | w x8]`) and
Qwen with `R = 128` of 128.

Channel map within a head: channel `j` and `j + 48` form a rotation pair for
`j < 48`; `j in [0,16)` rotates by `t * inv_freq[j]`, `[16,32)` by `h *
inv_freq[j-16]`, `[32,48)` by `w * inv_freq[j-32]`. **Channels 96..127 are not
rotated.** This is rotate-half, not interleaved pairs, and the axis split is
`16/16/16`, not Wan's.

FFN (`F/dit:96-138`): `ff.net.0.proj: Linear(5376, 28672)` no bias, `(value,
gate) = chunk(2)`, `value * silu(gate)` (**value half first**, the opposite of
the Qwen MLP's naming), `ff.net.2: Linear(14336, 5376)` no bias.

### VSA-H3 (`F/vsa`, read in full)

`to_gate_compress` is the learned gate on VSA's pooled "compression" branch. The
base H3 checkpoint has no such weight and FastVideo zero-initializes it, which
makes the branch an exact no-op (`F/dit:191-220`). **This checkpoint ships it
and it is trained**: 50 tensors `[7168, 5376]` BF16, and a sample of four
512-value windows (blocks 0 and 49, start and middle) is 100 % nonzero with
`|w| <= 1.1e-4`. FastVideo tests `(weight != 0).any()` once and then runs the
branch (`F/dit:222-257`), so the reference output includes it. The values are
small (1300 steps at lr 2e-6 from zero), so its contribution is small, but it
is part of the trained function.

**Tiles** (`F/vsa:216-263`, `F/st/denoising:48-59`). `prefix_segments = (N_text,
N_cond, N_audio)` with zero-length segments dropped, so `(N, 2Na)` here.

* Prefix tiles: each segment is cut, in sequence order, into consecutive chunks
  of 64 rows; the last chunk of a segment may be short. Tiles are
  **segment-pure**: a tile never mixes text and audio rows.
* Video tiles: the token grid `(T', H', W') = (37, 24, 42)` is cut into
  `(4,4,4)` cubes, tiles enumerated `t`-tile, then `h`-tile, then `w`-tile;
  inside a tile the tokens keep the sub-cube's row-major `(t,h,w)` order
  (`F/vsa0:32-48`). Edge tiles are partial: sizes are the product of per-axis
  sizes `[4 x9, 1] x [4 x6] x [4 x10, 2]` (`F/vsa0:60-100`), so 64, 32, 16 or 8.
* Tile list = prefix tiles, then video tiles. Tile `i` owns slots `[64i,
  64i + size_i)` of a zero-initialized buffer of `n_tiles * 64` rows.

| | N=256, 5 s | N=256, 15 s |
|---|---|---|
| prefix tiles `P` | 4 + 7 = 11 | 4 + 19 = 23 |
| video tiles | 10 x 6 x 11 = 660 | 27 x 6 x 11 = 1782 |
| `n_tiles`, padded rows | 671, 42 944 | 1805, 115 520 |
| `k_vid = ceil(0.2 * video_tiles)` | 132 | 357 |
| keys seen by a video query tile | (132 + 11) x 64 = 9152 slots | (357 + 23) x 64 = 24 320 |

**Coarse scores** (`F/vsa:371-383`, `F/vsa:626-629`). Mean-pool q and k per tile
over the *valid* rows (sum in float32 over the zero-padded tile, divide by
`size_i`), per head: `scores = qbar kbar^T / sqrt(128)`, `[1, 56, n, n]`
float32. q and k here are post-norm, post-RoPE.

**Block mask** (`F/vsa:386-409`), "exempt" mode, per head:

```
k_vid = clamp(ceil((1 - sparsity) * n_video), 1, n_video)        # F/vsa0:161-163
if k_vid == n_video: mask = all True                              # sparsity 0 == dense
else:
    for every query tile i:  mask[i, P + topk(scores[i, P:], k_vid)] = True   # top-k over VIDEO columns only
    mask[:, :P] = True          # every query sees every text and audio tile ("exempt": they do not compete)
    mask[:P, :] = True          # text and audio QUERY tiles are dense: they see everything
```

So text/audio rows are dense in both directions; only video-to-video attention
is sparsified, and the per-row key count is non-uniform (`n` for prefix rows,
`P + k_vid` for video rows). The alternative "compete" mode (prefix columns
enter a single top-k of size `k_vid + P`) is an ablation switch and is not what
this checkpoint runs (`F/st/denoising:159-162`).

**Fine attention.** A query row in tile `i` attends to the valid rows of every
tile `j` with `mask[h, i, j]`, ordinary softmax over that set, scale
`1/sqrt(128)`; pad slots are excluded through the size vector (`F/vsa:738-744`).

**Compression branch and combine** (`F/vsa:757-772`):

```
vbar  = mean-pool v per tile                                    # same pooling
out_c = softmax(scores, dim=-1) @ vbar                          # over ALL n tiles, no mask; [1, 56, n, 128]
out[row in tile i] = out_sparse[row] + out_c[i] * g[row]        # elementwise in (head, channel); applies to prefix tiles too
```

Then rows are scattered back to packed order and projected by `to_out`.

Relative to the backend's existing Wan VSA (`crates/fastvideo-cudarc/src/wan/vsa.rs`),
which already has tile-mean pooling, the coarse softmax, top-k, a fine stage
at head dim 128 and `coarse * gate + sparse`, H3 needs: (1) a tile plan with 1-D
segment-pure prefix tiles ahead of the video cubes (the existing
`vsa_plan_upload(slot_src, block_sizes)` already takes an arbitrary slot map);
(2) top-k restricted to columns `[P, n)` plus forced columns `[0, P)`; (3) dense
query rows for tiles `< P`. A decomposition that reuses existing kernels: run
the `P * 64 <= ~1.5k` prefix queries through ordinary dense SDPA against all `S`
keys, and the video queries through the fine stage with a uniform selected list
`[0..P) ++ topk`, length `P + k_vid`.

Top-k is discontinuous: a rounding-level score difference changes the selected
set. VSA outputs are therefore not comparable to a reference at tight
tolerance; validate VSA structurally (section j).

### Output heads (`F/dit:950-961`)

```
y = RMSNorm(x; norm_out.norm, 1e-5) * (1 + scale_out[ti]) + shift_out[ti]      # ti = timestep_index per row; per timestep, NOT per modality
y = float32(y)
video_velocity = proj_out(y)[video_idx]            # Linear 5376 -> 96, bias, float32  -> [1, T*1008, 96]
audio_velocity = audio_proj_out(y)[audio_idx]      # Linear 5376 -> 32, bias, float32  -> [1, 2Na, 32]
```

Both heads are defined on every row; only the video rows of `proj_out` and the
audio rows of `audio_proj_out` are read, so compute each head on its own rows
only. Text rows produce no output. Video rows unpatchify as above; audio rows
unpack as in section d.

## f. Sampling loop

State: `video_rows [T*1008, 96]` and `audio_rows [2Na, 32]`, float32, initialized
to the noise of section a. Convention (`D/sched:15-32`): rectified flow with
`x_t = t * x0 + (1 - t) * noise`, `t = 1 - sigma`, and the model predicts a
**data-ward velocity** `v = x0 - noise`, so

```
x0 = x_t + sigma * v                                   # note the PLUS; diffusers' other flow schedulers use minus
```

For step `i = 0..7`, one forward serves both modalities
(`F/st/denoising:179-237`):

```
(v_video, v_audio) = DiT(video_rows, audio_rows, text; timestep = sorted_unique(t_video[i], t_audio[i]), ...)
for m in (video, audio), in float32 (D/sched:264-277):
    sigma_t = 1 - timestep_m[i]                        # recovered from the float32 TIMESTEP, not read off the grid
    x0      = x_m + sigma_t * v_m
    r       = sigma_m[i+1] / sigma_m[i]                # from the sigma grid
    x_m     = r * x_m + (1 - r) * x0
```

`eta = 0`: no noise is re-injected between steps, unlike this repo's Wan DMD
loop (`schedulers/dmd.rs`), which re-noises with fresh Gaussian noise each step.
On the last step `sigma[8] = 0`, `r = 0`, and `x = x0`. The 9-point grid maps to
8 forwards as `forward i` at `sigma[i]`, stepping to `sigma[i+1]`; the terminal
0 has no forward. `1 - (1 - sigma)` differs from `sigma` in the last float32
bit below 0.5, which is why the reference keeps the two sources apart; the
difference is ~1e-8 and immaterial to parity, but it is what
`H3Schedule::step_coeffs` reproduces.

After the loop: unpatchify video rows, denormalize, VAE decode (section c);
unpack audio rows, denormalize, audio decode (section d).

## j. Oracle plan

`scripts/gpu/h3_oracle.py`, same convention as `upstream_oracle.py`: reference
implementations on the same weights, seeded **CPU** noise saved alongside the
outputs, everything saved as float32 in one safetensors plus a meta JSON.
"Everything" includes ids, tags and row indices (exact in float32), because
`fastvideo-gpucheck`'s `st::load` rejects any other dtype.

With `--llm-out` it also writes the file the generic stage `fv-gpucheck llm
--weights <text_encoder dir> --family qwen3-vl-32b --oracle <file>` consumes
(`crates/fastvideo-gpucheck/src/llm_oracle.rs`): `input_ids [S]`, `positions
[S]` (`0..S-1`, the 1-D positions all three mrope axes share for text),
`attend [S]` (all ones: one unpadded sequence), and `hidden_<k> [1, S, 5120]`
for taps `1, 8, 50`: tap 50 is what H3 consumes, 1 and 8 are early-divergence
probes. The reference runs in bf16 on the GPU (float32 is 133 GB); the meta
says so.
Stages free their model before the next, so it runs on one 96 GB card: the text
encoder is 66.7 GB in bf16, the diffusers DiT 66.2 GB (it ignores the 3.85 GB
of gates) plus a few GB of activations with flash SDPA at `S = 38k`.

**What the diffusers oracle can and cannot judge.** diffusers has no VSA and no
`to_gate_compress`, so its DiT forward is *dense attention without the gate
branch*. That is the right reference for our **dense mode**, which exercises
every weight, the packing, RoPE, the AdaLN table, both heads and the scheduler.
It is not the trained function. VSA-H3 is validated separately (below). The DiT
also necessarily runs in bf16 (float32 would be 140 GB), so its limits are
looser than the float32 stages'.

**Why the ladder is gated on its first three steps only.** Against the bf16
reference the per-step error roughly doubles (video 2.4e-4 -> 4.0e-1, audio
4.5e-4 -> 2.6e-1), and LTX-2 behaves the same against its own bf16 reference.
A few-step distilled sampler feeds each forward's rounding-level divergence
(1.3e-2 for one forward) back into the next while the carried-noise share
`sigma'/sigma` falls to zero, so two correct bf16 implementations finish on
different, equally valid samples; the decoded clip is coherent and on-prompt. A
wrong sign, shift or ratio is visible at steps 0..2, and is pinned exactly (2e-5
over all 8 steps, float32, CPU) by `h3/reference_tests.rs` against diffusers'
own scheduler. Measured end to end (RTX PRO 6000, 5 s, VSA-H3): text 10.6 s,
DiT load 13.0 s, denoise 94 s (11.8 s/step; dense is 87 s/step), video decode
22.9 s, total 145.5 s, peak 53.6 GB. `FASTVIDEO_SDPA=flash` is ~20x slower than
the dense path at 38k rows and is not a speed option.

The text limits are wide because the reference itself is bf16 over 50 layers;
once a first run exists, tighten each to about 3x the observed value, as was
done for Wan. `vae_video_raw` is compared **before** the ImageNet de-normalize
and clamp (a clamp hides errors), and the meta records the reference's own
fp16-autocast-vs-float32 gap so a bf16-Linear decoder has a measured budget.
The fixed latents are seeded normals in DiT space (the port applies
`latents_mean/std` itself, which puts that step under test).

The three comparisons of `upstream_oracle.py` carry over: `text` (ours vs
oracle), `dit` (our DiT on the *oracle* text and noise), `e2e` (our DiT on *our*
text).

**Validating VSA-H3**, which no diffusers tensor can:

1. *Structural*: our VSA at sparsity 0 (k = all) with the gate disabled must
   equal our dense path; FastVideo reports <= 2e-4 for the same identity
   (`F/st/denoising:184-186`). Then with the gate enabled and sparsity 0, the
   difference from dense must equal the compression term alone.
2. *Host reference*: a plain-Rust implementation of the mask rule and combine
   of section e on a small grid (the existing `vsa_attention_host` pattern),
   against the device path, including partial tiles and an odd tile count.
3. *External*: a FastVideo run of this checkpoint (`output_type="latent"`,
   `--vsa-kernel triton`, same seed and injected `latents` / `audio_latents`,
   which its latent-preparation stage accepts, `F/st/latent_preparation:328-348`)
   is the only true end-to-end reference for the trained recipe. Because top-k
   selection amplifies rounding, compare it perceptually / statistically (latent
   cosine per step, decoded PSNR), not element-wise. Not scripted here; it needs
   a FastVideo install with its Triton kernels on sm_120.
