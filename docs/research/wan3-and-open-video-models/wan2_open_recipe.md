# Wan 2.1 / 2.2: the documented, reproducible recipe (as of 2026-10-21)

Scope: what Alibaba's Wan team has actually published about how Wan 2.1 and Wan 2.2 were built (architecture, objective, data, schedule, infra), what code exists to train them, and what is left undocumented. Wan 3.0 is out of scope (another researcher). Primary sources: the Wan 2.1 technical report (arXiv 2503.20314, v1 2025-03-26, v2 2025-04-19), the Wan2.1 and Wan2.2 GitHub repos and config files, the Hugging Face model cards, and the third-party training frameworks' own docs. Numbers are quoted as the source gives them.

Note on dates: the Wan2.1 README dates the first weight release to 2025-02-25 and the technical report to 2025-03-21; the Wan2.2 README dates its release to 2025-07-28 ([Wan2.1 README](https://github.com/Wan-Video/Wan2.1); [Wan2.2 README](https://github.com/Wan-Video/Wan2.2)).

## Key question 1: Exact architecture of the Wan 2.1 (1.3B, 14B) and Wan 2.2 (A14B MoE, TI2V-5B) DiTs and VAEs, with HF ids and licences

### Takeaway
All Wan 2.x weights are Apache-2.0 and the DiT is a plain, fully-specified pre-norm DiT with full 3D attention, 3D RoPE, umT5-XXL cross-attention and a shared adaLN MLP; the exact dims are in the official config files. Wan 2.2 A14B reuses the Wan 2.1 14B architecture and VAE twice (two timestep-partitioned "experts" switched at a fixed boundary), while TI2V-5B is a new dense 30-layer/3072-dim model on a new 4x16x16 VAE.

### Cited Findings

**Model catalogue, HF ids, licence**
- Wan 2.1 models and HF ids: `Wan-AI/Wan2.1-T2V-14B` (480P+720P), `Wan-AI/Wan2.1-I2V-14B-720P`, `Wan-AI/Wan2.1-I2V-14B-480P`, `Wan-AI/Wan2.1-T2V-1.3B` (480P), `Wan-AI/Wan2.1-FLF2V-14B-720P`, `Wan-AI/Wan2.1-VACE-1.3B`, `Wan-AI/Wan2.1-VACE-14B`; "The models are licensed under Apache 2.0" — [Wan2.1 README](https://github.com/Wan-Video/Wan2.1)

- Wan2.2-TI2V-5B card: "The models in this repository are licensed under the Apache 2.0 License"; metadata `apache-2.0` — [HF Wan2.2-TI2V-5B](https://huggingface.co/Wan-AI/Wan2.2-TI2V-5B); same statement on [HF Wan2.2-T2V-A14B](https://huggingface.co/Wan-AI/Wan2.2-T2V-A14B)

**Wan-VAE (2.1)**
- 3D causal VAE: video of shape (1+T)xHxWx3 is compressed to [1+T/4, H/8, W/8] with 16 latent channels (4x8x8 compression); first frame compressed spatially only (MagViT-v2 style); all GroupNorm replaced by RMSNorm to keep temporal causality and enable the feature cache; input channels of the spatial-upsampling layer halved ("33%" inference memory reduction); "compact model size of only 127M parameters" — [arXiv 2503.20314 (HTML)](https://arxiv.org/html/2503.20314)
- Feature cache: inference is chunked, each chunk covers one latent's frames with at most 4 frames per chunk; with kernel 3 / stride 1 two frames are cached, the first chunk is zero-padded with two dummy frames; with 2x temporal downsampling (stride 2) non-initial chunks use a single-frame cache; the mechanism "supports stable inference for infinite-length videos" — [arXiv 2503.20314](https://arxiv.org/html/2503.20314)
- VAE training is three-stage: (1) a 2D image VAE of the same structure trained on images; (2) inflate to 3D causal and train on low-res video (128x128, 5 frames) with L1 reconstruction + KL + LPIPS weighted 3, 3e-6 and 3; (3) high-quality video at varied resolutions and frame counts with an added GAN loss from a 3D discriminator — [arXiv 2503.20314](https://arxiv.org/html/2503.20314)
- Comparison table (200 videos, 25 frames, 720x720): Wan-VAE 4x8x8 / 16 ch; Open-Sora-Plan 4x8x8 / 4; SVD 1x8x8 / 4; Step-Video 8x16x16 / 64; Mochi 6x8x8 / 12; HunyuanVideo and CogVideoX share Wan's rate and channel count; "our VAE's reconstruction speed is 2.5 times faster than the existing SOTA method (i.e., HunYuan Video)" on the same hardware; PSNR results are given only as a plot (Fig. 7) — [arXiv 2503.20314](https://arxiv.org/html/2503.20314)
- VAE ablation (Table 5, FID lower is better): Wan-VAE 42.60 vs "VAE-D" 44.21 at the first checkpoint and 40.55 vs 41.16 at the second; the table labels the checkpoints 10k/15k steps while the prose says 100,000/150,000 (internal inconsistency in the report) — [arXiv 2503.20314](https://arxiv.org/html/2503.20314)
- README summary: Wan-VAE "can encode and decode unlimited-length 1080P videos without losing historical temporal information" — [Wan2.1 README](https://github.com/Wan-Video/Wan2.1)

**Wan 2.1 DiT**
- Official config table: 1.3B = dim 1536, in/out dim 16, FFN 8960, freq dim 256, 12 heads, 30 layers; 14B = dim 5120, in/out 16, FFN 13824, freq 256, 40 heads, 40 layers — [Wan2.1 README](https://github.com/Wan-Video/Wan2.1); confirmed in config `wan_t2v_1_3B.py`: `dim=1536, ffn_dim=8960, freq_dim=256, num_heads=12, num_layers=30, window_size=(-1,-1), qk_norm=True, cross_attn_norm=True, eps=1e-6, vae_checkpoint='Wan2.1_VAE.pth', vae_stride=(4,8,8), patch_size=(1,2,2)` — [wan_t2v_1_3B.py](https://raw.githubusercontent.com/Wan-Video/Wan2.1/main/wan/configs/wan_t2v_1_3B.py)
- Patchify: 3D conv with kernel (1,2,2); sequence length L = (1+T/4) x H/16 x W/16; text conditioning via cross-attention in each block; full spatio-temporal attention — [arXiv 2503.20314](https://arxiv.org/html/2503.20314)
- Time embedding / modulation: an MLP (Linear + SiLU) predicts six modulation parameters, shared across all blocks, each block learning its own set of biases; reported "about a 25% parameter reduction" — [arXiv 2503.20314](https://arxiv.org/html/2503.20314); README restates it ("shared MLP ... predicts six modulation parameters ... each block learns its own set of biases") — [Wan2.1 README](https://github.com/Wan-Video/Wan2.1)
- Code-level details (official `wan/modules/model.py`): 3D RoPE built with `rope_params(1024, d - 4*(d//6))` for time and `rope_params(1024, 2*(d//6))` each for H and W (theta 10000, computed in float64; for head_dim 128 that is 22/21/21 complex pairs); RoPE applied to Q,K only, not in cross-attention; `qk_norm=True` uses `WanRMSNorm` on q and k over the full dim; block norms are `nn.LayerNorm` with `elementwise_affine=False`, `norm3` (pre-cross-attn) has affine when `cross_attn_norm=True`; per-block `modulation = nn.Parameter(torch.randn(1, 6, dim) / dim**0.5)` added to the shared time embedding and split into shift/scale/gate for attn and FFN; cross-attention output is added ungated; FFN is Linear-GELU(tanh)-Linear; `patch_embedding = nn.Conv3d(in_dim, dim, kernel_size=patch_size, stride=patch_size)` with `in_dim=16`; `text_embedding = Linear(4096, dim)-GELU(tanh)-Linear(dim, dim)`, text zero-padded to 512 tokens; time: `sinusoidal_embedding_1d(256, t)` -> Linear(256,dim)-SiLU-Linear(dim,dim), then `time_projection = SiLU + Linear(dim, dim*6)`; head: LayerNorm, (1+scale)+shift, zero-initialised Linear to prod(patch)*out_dim; I2V variant adds `MLPProj(1280 -> dim)` for CLIP image tokens prepended to the text context and a channel-concatenated conditioning latent — [model.py](https://raw.githubusercontent.com/Wan-Video/Wan2.1/main/wan/modules/model.py)
- I2V conditioning in the report: I2V input has "2xc+s" channels versus "c" for T2V, so "an additional projection layer is employed, which is initialized with zero values"; CLIP image features pass through "a three-layer multi-layer perceptron (MLP)" and are injected "via decoupled cross-attention"; diffusers names the image encoder as CLIP "clip-vit-huge-patch14" — [arXiv 2503.20314](https://arxiv.org/html/2503.20314); [diffusers Wan docs](https://huggingface.co/docs/diffusers/main/en/api/pipelines/wan)
- Shared runtime config (inherited by all 2.1/2.2 tasks): `t5_model='umt5_xxl'`, `text_len=512`, `param_dtype=bfloat16`, `num_train_timesteps=1000`, `sample_fps=16`, `frame_num=81`, plus a fixed Chinese negative prompt — [Wan2.2 shared_config.py](https://raw.githubusercontent.com/Wan-Video/Wan2.2/main/wan/configs/shared_config.py)
- Text encoder: umT5; "umT5 embedding sequence of 512 tokens"; ablation lists umT5 at 5.3B parameters vs Qwen2.5-7B-Instruct and GLM-4-9B — [arXiv 2503.20314](https://arxiv.org/html/2503.20314)

**Wan 2.2 A14B MoE**
- "each A14B expert has about 14B parameters ... total is 27B, but only 14B are active per step"; high-noise expert handles early denoising (overall layout), low-noise expert the later steps (detail refinement) — [Wan2.2 README](https://github.com/Wan-Video/Wan2.2)
- Switch rule: SNR-based; "We define a threshold step t_moe corresponding to half of the SNR_min, and switch to the low-noise expert when t < t_moe" — [HF Wan2.2-T2V-A14B](https://huggingface.co/Wan-AI/Wan2.2-T2V-A14B)
- Official T2V-A14B config: `dim=5120, ffn_dim=13824, freq_dim=256, num_heads=40, num_layers=40, vae_stride=(4,8,8), patch_size=(1,2,2)`, `low_noise_checkpoint='low_noise_model'`, `high_noise_checkpoint='high_noise_model'`, `sample_shift=12.0, sample_steps=40, boundary=0.875, sample_guide_scale=(3.0, 4.0)` (low-noise 3.0, high-noise 4.0) — [wan_t2v_A14B.py](https://raw.githubusercontent.com/Wan-Video/Wan2.2/main/wan/configs/wan_t2v_A14B.py)
- Official I2V-A14B config: same dims; `sample_shift=5.0, sample_steps=40, boundary=0.900, sample_guide_scale=(3.5, 3.5)`; no CLIP image encoder configured (unlike Wan 2.1 I2V) — [wan_i2v_A14B.py](https://raw.githubusercontent.com/Wan-Video/Wan2.2/main/wan/configs/wan_i2v_A14B.py)
- Diffusers exposes this as `transformer` (high-noise) + `transformer_2` (low-noise) with `boundary_ratio`: "The actual boundary timestep is calculated as boundary_ratio * num_train_timesteps ... transformer handles timesteps >= boundary_timestep and transformer_2 handles timesteps < boundary_timestep", with a separate `guidance_scale_2` for the low-noise stage; LoRAs load into the first denoiser by default unless `load_into_transformer_2=True` — [diffusers Wan docs](https://huggingface.co/docs/diffusers/main/en/api/pipelines/wan)
- The validation-loss ablation on the model card compares four settings: baseline Wan2.1 (no MoE), Wan2.1 + high-noise expert, Wan2.1 + low-noise expert, and Wan2.2 (MoE); "Wan2.2 (MoE) (our final version) achieves the lowest validation loss" — [HF Wan2.2-T2V-A14B](https://huggingface.co/Wan-AI/Wan2.2-T2V-A14B); numeric loss values are not given in text (figure only).
- musubi-tuner note: the Wan2.2 VAE "is for the 5B model and is not compatible with 14B"; A14B uses the Wan 2.1 VAE — [musubi-tuner docs/wan.md](https://github.com/kohya-ss/musubi-tuner/blob/main/docs/wan.md)

**Wan 2.2 TI2V-5B**
- "a 5B model built with our advanced Wan2.2-VAE that achieves a compression ratio of 16x16x4"; with the patchify layer "the total ratio is 4x32x32"; supports 720P at 24 fps; "can generate a 5-second 720P video in under 9 minutes on a single consumer-grade GPU"; runs on "a GPU with at least 24GB VRAM (e.g, RTX 4090 GPU)" with `--offload_model True --convert_model_dtype --t5_cpu` — [HF Wan2.2-TI2V-5B](https://huggingface.co/Wan-AI/Wan2.2-TI2V-5B)
- Official TI2V-5B config: `vae_checkpoint='Wan2.2_VAE.pth', vae_stride=(4,16,16), patch_size=(1,2,2), dim=3072, ffn_dim=14336, freq_dim=256, num_heads=24, num_layers=30, window_size=(-1,-1), qk_norm=True, cross_attn_norm=True, eps=1e-6, sample_fps=24, sample_shift=5.0, sample_steps=50, sample_guide_scale=5.0, frame_num=121`, T5 = `models_t5_umt5-xxl-enc-bf16.pth` — [wan_ti2v_5B.py](https://raw.githubusercontent.com/Wan-Video/Wan2.2/main/wan/configs/wan_ti2v_5B.py)
- 720P sizes for TI2V are `1280*704` or `704*1280` — [Wan2.2 README](https://github.com/Wan-Video/Wan2.2)

### Inferences
- Token budgets (derived from configs above): Wan 2.1/2.2-14B at 81 frames 1280x720 -> 21 latent frames x (90/2) x (160/2) = 75,600 tokens; TI2V-5B at 121 frames 1280x704 -> 31 latent frames x (44/2) x (80/2) = 27,280 tokens, i.e. the 5B model attends over ~36% of the tokens of the 14B model for a longer clip at higher fps, which is the whole reason it fits a 4090.
- The Wan 2.2 "MoE" is not token-routed MoE; it is two full dense 14B DiTs selected by timestep, so training compute per step equals one 14B model and memory for serving equals two. Any reproduction can train the two experts as independent fine-tunes with disjoint timestep ranges (which is exactly how DiffSynth and musubi train it, see Q4).
- `boundary=0.875` (T2V) / `0.900` (I2V) means the high-noise expert is used only for t in [875, 1000] of the 1000-step schedule; with the recommended `sample_shift=12` for T2V, a large share of the 40 sampling steps nonetheless lands in that range (shift concentrates steps at high noise), which is consistent with the "layout" role.
- The Wan 2.2 VAE's 16 latent channels vs 4x16x16 compression is not stated in text; the latent channel count of the Wan2.2 VAE is given only by the weights (diffusers config lists it as 48 channels, but I did not fetch that file — see Gaps).

### Gaps
- The report does not give the DiT head dim explicitly (dim/heads = 128 for all three sizes is derived from the configs).
- No official text states the Wan2.2-VAE latent channel count, decoder architecture, or its training recipe; the 5B VAE is documented only by its compression ratio and the config file.
- The exact value of SNR_min used to set t_moe, and how 0.875 / 0.9 follow from "half of SNR_min", are not given anywhere official.

## Key question 2: What the Wan 2.1 technical report says about data, training stages, compute and infrastructure

### Takeaway
The report is explicit about the pipeline shape (four-step cleaning, 100-cluster quality sampling, six-tier motion classification, in-house dense captioner), the objective (flow matching, logit-normal t, velocity MSE, AdamW lr 1e-4) and the curriculum (256px T2I -> 192px/16fps/5s video -> 480p -> 720p -> 480p/720p post-training), but gives no absolute dataset sizes beyond "billions of images and videos" / "O(1) trillions of tokens", no batch sizes or step counts for pre-training, and no GPU counts or GPU-hours for any model.

### Cited Findings

**Data (Section 3)**
- Overall: data is "billions of videos and images"; the intro also says "O(1) trillions of tokens"; sources are "internal copyrighted sources and publicly accessible data", deduplicated — [arXiv 2503.20314](https://arxiv.org/html/2503.20314)
- Pre-training cleaning, "fundamental dimensions" step: lightweight OCR text-coverage detector; LAION-5B aesthetic classifier (images); internal NSFW model; watermark/logo detection with cropping during training; heuristic black-border cropping; overexposure classifier; synthetic-image classifier (contamination "<10%" is said to noticeably degrade the model); internal blur scorer; videos must exceed "4 seconds"; resolution thresholds vary by stage; this stage removed "approximately 50%" of the initial dataset — [arXiv 2503.20314](https://arxiv.org/html/2503.20314)
- Visual quality step: clustering into 100 clusters with per-cluster sampling to preserve long-tail data; manual 1-5 scoring on samples trains an expert scorer applied to the whole set — [arXiv 2503.20314](https://arxiv.org/html/2503.20314)
- Motion quality step: six tiers (Optimal motion, Medium-quality motion, Static Videos, Camera-driven Motion, Low-quality Motion, Shaky camera footage); static and camera-driven get lower sampling priority; low-quality and shaky are excluded — [arXiv 2503.20314](https://arxiv.org/html/2503.20314)
- Visual text: "hundreds of millions" of synthesised images with Chinese characters on white background plus real text images; multiple OCR models read EN/ZH text; Qwen2-VL writes captions containing the text — [arXiv 2503.20314](https://arxiv.org/html/2503.20314)
- Figure 3 shows the data mix across training phases (motion/quality/category proportions adjusted per phase) — [arXiv 2503.20314](https://arxiv.org/html/2503.20314)
- Post-training data: images keep the "top 20%" by expert-predicted score, balanced by style/category, plus manual collection, giving "millions" of curated images; videos are filtered by a visual-quality classifier and a motion-quality classifier selecting "millions" of simple-motion and "millions" of complex-motion videos across 12 major categories — [arXiv 2503.20314](https://arxiv.org/html/2503.20314)
- Captioner (Section 3.3): internal LLaVA-style model (ViT + two-layer projector + Qwen LLM); images up to seven patches each pooled to 12x12; video sampled at 3 fps up to 129 frames with every fourth frame kept at full resolution and the rest globally average-pooled ("slow-fast"); slow-fast raised VideoMME from 67.6% to 69.1%; three-stage training with lr 1e-3 then 1e-5 (LLM/MLP) and 1e-6 (ViT); evaluated on ten dimensions with 1,000 videos each against Gemini 1.5 Pro — [arXiv 2503.20314](https://arxiv.org/html/2503.20314)
- Each image/video gets multiple captions varying in length (long/medium/short) and style (formal/informal/poetic); at inference user prompts are rewritten with Qwen2.5-Plus to match caption distribution — [arXiv 2503.20314](https://arxiv.org/html/2503.20314)
- Image data is "nearly ten times larger than its video counterpart" (Sec. 5.3) — [arXiv 2503.20314](https://arxiv.org/html/2503.20314)
- README restates only: "four-step data cleaning process focusing on fundamental dimensions, visual quality and motion quality" — [Wan2.1 README](https://github.com/Wan-Video/Wan2.1)

**Objective and schedule (Section 4.2)**
- Flow matching: x_t = t x_1 + (1-t) x_0 with x_0 ~ N(0, I); velocity target v_t = x_1 - x_0; MSE on velocity; "t ... sampled from a logit-normal distribution"; no timestep shift is stated for training — [arXiv 2503.20314](https://arxiv.org/html/2503.20314)
- Pre-training: text-to-image at 256px first (the 14B model "is initialized with 256px text-to-image pre-training"); then three joint image-video stages: (1) 256px images + 5-second clips at "192px resolution, 16 fps"; (2) 480px images and video, fixed 5-second duration; (3) 720px images and 5-second clips; the report motivates the curriculum by the cost of "81 frames for 1280x720 video" (rendered as "8181" in the HTML) — [arXiv 2503.20314](https://arxiv.org/html/2503.20314)
- Optimiser: "bf16-mixed precision", AdamW, weight decay 1e-3, initial lr 1e-4, reduced when FID and CLIP score plateau; no batch size or step counts for pre-training are given — [arXiv 2503.20314](https://arxiv.org/html/2503.20314)
- Post-training (4.2.3): same architecture and optimiser, initialised from the pre-trained checkpoint, trained jointly at 480p and 720p on the post-training set; the term "SFT" appears only in Sec. 5.1.3 (I2V, where an image encoder is added during SFT and experiments use two pre-trained checkpoints at 480p and 720p); no RLHF/DPO/preference alignment is described anywhere in the report — [arXiv 2503.20314](https://arxiv.org/html/2503.20314)
- Inference defaults: ~50 sampling steps; diffusers/official recipes use `flow_shift` 3.0 for 480P and 5.0 for 720P with UniPC — [arXiv 2503.20314](https://arxiv.org/html/2503.20314); [diffusers Wan docs](https://huggingface.co/docs/diffusers/main/en/api/pipelines/wan)

**Ablations (Section 4.7)**
- adaLN: four variants trained 200,000 steps on T2I with batch size 1536, compared by L2 training loss: full-shared 1.3B (30 layers) slightly higher loss; full-shared 1.5B (35 layers) beats half-shared 1.5B at equal params; non-shared 1.7B does not beat full-shared 1.5B; conclusion "focusing on model depth rather than the parameters in AdaLN leads to better performance" — [arXiv 2503.20314](https://arxiv.org/html/2503.20314)
- Text encoder (Table 6, FID): umT5 43.01; Qwen-VL-7B last layer 43.72; Qwen-VL-7B second-to-last 42.91; Qwen2.5-7B-Instruct and GLM-4-9B compared only on loss curves (Fig. 17), where umT5 is best — [arXiv 2503.20314](https://arxiv.org/html/2503.20314)

**Infrastructure (Section 4.3, 4.4)**
- Workload: DiT is "more than 85%" of training compute; at 1 million tokens attention "can account for up to 95%" of end-to-end time; attention cost factor "4 for the forward pass and 8 for the backward pass"; activation coefficient gamma for DiT "can exceed 60" vs "34" for LLMs; a 14B DiT at 1M tokens and micro-batch 1 has activation memory that "can exceed 8 TB" — [arXiv 2503.20314](https://arxiv.org/html/2503.20314)
- Parallelism: DP + FSDP for parameter sharding; Context Parallel (Ulysses + Ring Attention) along the sequence; Megatron TP/SP along hidden dim; 2D CP with Ring outer / Ulysses inner; at 256K sequence on 16 GPUs across 2 machines CP overhead drops "from over 10%" to "below 1%"; Figure 11 example on 128 GPUs: Ulysses=8, Ring=2, FSDP=32, DP=4, global batch "8 times" micro-batch; VAE/text-encoder time share reduced "to 1/CP" — [arXiv 2503.20314](https://arxiv.org/html/2503.20314)
- Memory: activation offload over PCIe overlapped with "1 to 3 DiT layers" of compute; offloading prioritised over gradient checkpointing, GC applied to high memory-to-compute layers — [arXiv 2503.20314](https://arxiv.org/html/2503.20314)
- Cluster: Alibaba Cloud scheduling, slow-machine detection, self-healing restart; no cluster size, GPU type, GPU-hours, MFU or throughput numbers given — [arXiv 2503.20314](https://arxiv.org/html/2503.20314)
- Inference infra: CP with FSDP gives "nearly linear speedup" on 14B (Fig. 12); CFG cache + attention cache "1.62x" on 14B T2V; FP8 on all DiT GEMMs gives "1.13x" DiT speedup (FP8 GEMM "twice the performance of BF16 GEMM"); 8-bit FlashAttention (Int8 QK^T, FP8 PV) "achieves 95% MFU on NVIDIA H20 GPUs" and "more than 1.27x" overall — [arXiv 2503.20314](https://arxiv.org/html/2503.20314)
- Limitations (Sec. 6): "preserving fine-grained details in scenarios involving large motion remains a challenge"; "Inference on a 14B model currently requires approximately 30 minutes on a single head-end GPU" without optimisation; limited domain expertise (education, medicine given as examples); conclusion says future work is scaling data and architecture — [arXiv 2503.20314](https://arxiv.org/html/2503.20314)
- Consumer efficiency claims: T2V-1.3B needs "8.19 GB VRAM" and makes a 5-second 480P video on an RTX 4090 in "about 4 minutes" without quantisation — [Wan2.1 README](https://github.com/Wan-Video/Wan2.1)

### Inferences
- Combining the Fig. 11 example (128 GPUs = Ulysses 8 x Ring 2 x DP 4 with FSDP 32) with the 256K-token/16-GPU CP example suggests the 14B 720p runs used CP degree 16 per sample and ~128-GPU-scale job units, but the report never states total cluster size or how many such units ran; treat any total-compute estimate as unsupported.
- The absence of a training shift while inference uses shift 3-12 implies the training noise distribution (logit-normal) and inference schedule were tuned separately; a reproducer must pick both.
- The VAE ablation checkpoints (100k/150k steps per prose) hint that the DiT ablations were run at order-1e5 steps on 1.3-1.7B models with batch 1536 for T2I, giving a rough scale for "small" Wan experiments.

### Gaps
- No absolute image/video counts, hours of video, or token counts beyond "billions" / "O(1) trillions of tokens" (the README does not state "1.5 billion videos / 10 billion images"; I found no official source for such numbers).
- No per-stage step counts, batch sizes, learning-rate schedule values, warmup, or EMA for pre-/post-training.
- No GPU type (beyond the H20 inference MFU note), GPU count, GPU-hours, MFU or wall-clock for any Wan 2.1 model.
- No RL / preference-alignment / reward-model stage is described.

## Key question 3: What is documented about Wan 2.2's changes and a Wan 2.2 technical report

### Inferences
- Because A14B keeps the Wan 2.1 14B dims and VAE, the simplest reading is that both experts were initialised from (or trained the same way as) the Wan 2.1 14B backbone and then specialised on disjoint timestep ranges; the model-card ablation (Wan2.1 + one 2.2 expert hybrids) is consistent with the experts being drop-in replacements for the 2.1 model on their ranges. This is not stated officially.
- "Wan2.2 also accepts `--guidance_scale_high_noise`" and the official (3.0, 4.0) T2V scales show the two experts were tuned for different CFG; a reproducer should expect to tune CFG per expert.
- The 4x16x16 VAE and 24 fps / 121 frames combination was chosen so a 5 s 720P clip fits a 24 GB card; it is a design for inference cost, not a quality claim (no VAE reconstruction metrics for Wan2.2-VAE are published).

### Gaps
- No Wan 2.2 technical report, no training hyperparameters, no data sizes (only the relative +65.6%/+83.2%), no GPU counts, no description of how aesthetic labels enter the model (caption text vs. conditioning), and no Wan2.2-VAE architecture/training recipe have been published as of 2026-10-21.
- The Wan-Bench 2.0 numbers and the MoE validation-loss values exist only as images on the cards.
- Wan2.2-S2V has a PDF report and Wan-Animate has a project page; I did not verify arXiv ids for them (search did not surface them), and they are application models, out of the base-recipe scope.

## Key question 4: Which official or third-party code trains Wan models, and what hardware do they document

### Inferences
- The only place a Wan-shaped pre-training loop at multi-node scale is documented in the open is FastVideo (HSDP + SP + precomputed latents, 64 H200 runs) and DiffSynth (DeepSpeed ZeRO-3 full training); both are built for fine-tune/distillation data volumes (10^5-10^6 latents), not for "billions" of clips, so a from-scratch reproduction would need its own data loader, curriculum and multi-stage orchestration on top of them.
- The DiffSynth boundary values (0.417 in its own normalised space mapping to timestep 875) show the expert split is implemented purely by restricting the sampled timestep range during training; no routing network exists to train.
- Consumer-GPU fine-tuning is realistic only for LoRA (musubi: 24 GB; DiffSynth: 8 GB inference floor); full fine-tune of 14B needs ZeRO-3 / multi-GPU 80 GB-class nodes (DiffSynth), and the FastWan numbers (32-64 H200 for 12-52 h) are the best public calibration for distillation cost.

### Gaps
- No framework publishes a from-scratch Wan pre-training recipe or any run reproducing the Wan 2.1 1.3B from random init.
- DiffSynth gives no training VRAM/throughput numbers; finetrainers gives none; FastVideo gives GPU counts only for the FastWan distillation runs.
- I did not verify the FastWan2.1-T2V-14B card directly (the figures above came from a search summary of that page).

## Key question 5: Documented scaling or ablation findings that transfer to a new model on the same recipe

### Takeaway
The transferable, documented findings are few and modest: (a) 14B beats 1.3B by 0.035 on Wan-Bench and 2.26 points on VBench; (b) fully-shared adaLN plus extra depth beats per-layer adaLN at equal parameters; (c) a causal 4x8x8 VAE with RMSNorm beat the alternative "VAE-D" by ~1-2 FID; (d) umT5 edged Qwen-VL/Qwen2.5/GLM encoders on FID/loss; (e) Wan 2.2's timestep-split two-expert design achieved the lowest validation loss vs. the single-model and hybrid baselines. No scaling-law fit, compute-optimal analysis, or data-size ablation is published.

### Cited Findings
- Model size: Wan-Bench weighted scores (three dimensions: dynamic quality, image quality, instruction following; 14 metrics; weights from >5,000 pairwise human comparisons): Wan 14B 0.724, Wan 1.3B 0.689, Sora 0.700, Hunyuan 0.673; VBench totals: Wan 14B 86.22%, Wan 1.3B 83.96% — [arXiv 2503.20314](https://arxiv.org/html/2503.20314)
- Abstract claims the 14B model "demonstrates the scaling laws of video generation with respect to both data and model size", but the report body contains no scaling-law fit or loss-vs-size plot (only ablation loss curves, Figs. 16-17) — [arXiv 2503.20314 abstract](https://arxiv.org/abs/2503.20314); [arXiv 2503.20314 HTML](https://arxiv.org/html/2503.20314)
- adaLN ablation (200k T2I steps, batch 1536): full-shared adaLN at 35 layers (1.5B) beats half-shared 1.5B; non-shared 1.7B does not beat full-shared 1.5B; "focusing on model depth rather than the parameters in AdaLN leads to better performance"; the shared design saves "about 25%" of parameters — [arXiv 2503.20314](https://arxiv.org/html/2503.20314)
- VAE ablation: Wan-VAE FID 42.60 -> 40.55 vs VAE-D 44.21 -> 41.16 across two checkpoints — [arXiv 2503.20314](https://arxiv.org/html/2503.20314)
- Text encoder: umT5 FID 43.01 vs Qwen-VL-7B last layer 43.72 and second-to-last 42.91 ("comparable"); umT5 best on loss curves vs Qwen2.5-7B-Instruct and GLM-4-9B; stated reasons: multilingual (Chinese/English/visual text), better composition than unidirectional-attention LLMs, faster convergence at equal parameter scale — [arXiv 2503.20314](https://arxiv.org/html/2503.20314)
- Captioner: slow-fast video encoding improved VideoMME 67.6% -> 69.1%; the in-house captioner beats Gemini 1.5 Pro on event, camera angle, camera motion, style, object colour and loses on action, OCR, scene, category, counting — [arXiv 2503.20314](https://arxiv.org/html/2503.20314)
- Data hygiene: synthetic-image contamination "<10%" "noticeably degrade[s]" the model; the basic-dimension filter alone removes "approximately 50%" of raw data — [arXiv 2503.20314](https://arxiv.org/html/2503.20314)
- Compute structure: attention is up to 95% of step time at 1M tokens; activation memory coefficient >60 for DiT; this is what motivates the 192px->480p->720p curriculum and 2D CP — [arXiv 2503.20314](https://arxiv.org/html/2503.20314)
- MoE benefit (Wan 2.2): "Wan2.2 (MoE) (our final version) achieves the lowest validation loss" vs Wan2.1 and the two hybrid variants; same compute per step as one 14B model — [HF Wan2.2-T2V-A14B](https://huggingface.co/Wan-AI/Wan2.2-T2V-A14B); [Wan2.2 README](https://github.com/Wan-Video/Wan2.2)
- Distillation transfer: DMD + VSA sparse distillation to 3 steps with 32-64 H200 for 12-52 h on Wan 1.3B/14B/5B (see Q4) — [HF FastWan2.1-T2V-1.3B-Diffusers](https://huggingface.co/FastVideo/FastWan2.1-T2V-1.3B-Diffusers); [HF FastWan2.2-TI2V-5B-FullAttn-Diffusers](https://huggingface.co/FastVideo/FastWan2.2-TI2V-5B-FullAttn-Diffusers)
- Inference-time transfer: CFG/attention cache 1.62x, FP8 GEMM 1.13x on DiT, 8-bit FlashAttention 95% MFU on H20; LCM distillation to 4 steps gives 10-20x and 8-16 FPS streaming; int8 + TensorRT gives 8 FPS on a single 4090 (Fig. 31 caption says 20 FPS, inconsistent with the text) — [arXiv 2503.20314](https://arxiv.org/html/2503.20314)

### Inferences
- The 1.3B-vs-14B gap on Wan-Bench (0.035) is smaller than the 1.3B-vs-Hunyuan gap (0.016 in 1.3B's favour), supporting the report's own framing that a well-trained ~1-2B dense DiT on this recipe is competitive; a team with limited compute has a documented reason to start at 1.3B-scale.
- The adaLN result (prefer depth, share modulation) and the umT5 result are the only architecture ablations with numbers; everything else (RoPE split, QK-norm, patch (1,2,2), 16 latent channels) is adopted without published ablation.
- Wan 2.2's MoE result shows that splitting the timestep range between two independently fine-tuned copies lowers validation loss at constant per-step compute; this is cheap to reproduce from an existing dense checkpoint and is the most directly transferable 2.2 finding.

### Gaps
- No published data-scaling curve, no compute-optimal (tokens vs params) analysis, no VAE channel-count or compression-ratio ablation (the 4x16x16 Wan2.2-VAE has no published reconstruction numbers), no ablation of logit-normal vs shifted timestep sampling, and no quantified benefit of the cinematic aesthetic labels.

## What the Wan 2.1 technical report explicitly leaves undocumented (summary for the engineering decision)

Based on the fetched report, READMEs and model cards (all cited above), the following are NOT documented anywhere official as of 2026-10-21:
- Absolute dataset sizes (images, videos, hours, tokens) beyond "billions" and "O(1) trillions of tokens"; the raw source list; the per-stage data mix proportions (Figure 3 only).
- Training batch sizes, total steps, token counts per stage, LR decay schedule, warmup, EMA, gradient clipping, and the resolution/aspect-ratio bucketing scheme.
- Any timestep shift or SNR weighting used in training (only logit-normal sampling is stated; shift 3/5/12 appears only at inference).
- Cluster size, GPU type for training, GPU-hours, MFU or throughput for 1.3B or 14B.
- Any RL, DPO or reward-model post-training stage.
- The Wan2.2 experts' initialisation, training length, and the actual SNR_min; the Wan2.2-VAE design and training; the Wan2.2 data pipeline (only "+65.6% / +83.2%" and aesthetic labels).
- Training code: the official repos ship inference only; all training code is third-party (DiffSynth, musubi-tuner, finetrainers, FastVideo).
