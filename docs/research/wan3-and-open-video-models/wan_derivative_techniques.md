# Wan 2.1 / 2.2 derivative techniques and models (catalogue as of 2026-10-21)

Scope note: everything below was checked against primary pages (arXiv abstracts/HTML, GitHub READMEs, Hugging Face model cards, vendor blogs) on 2026-10-21. Numbers are quoted as the source states them. Where two sources disagree the disagreement is recorded rather than resolved. Items marked **weights-only** have released weights but no documented training method/recipe; items marked **no training code** have a paper but no runnable trainer.

Base facts used throughout:
- Wan2.1 main paper arXiv 2503.20314; Wan2.2 (T2V-A14B, I2V-A14B MoE; TI2V-5B dense) released July 28, 2025 under Apache-2.0, trained on "65.6% more images and 83.2% more videos" than Wan2.1; the A14B MoE has a high-noise and a low-noise expert (~14B each, 27B total, 14B active per step) switched at an SNR threshold; TI2V-5B uses the Wan2.2-VAE with 16×16×4 compression (4×32×32 with patchify) and "can generate a 5-second 720P video in under 9 minutes on a single consumer GPU"; Wan2.2-S2V-14B released Aug 26, 2025; Wan2.2-Animate-14B released Sep 19, 2025 — [Wan2.2 GitHub](https://github.com/Wan-Video/Wan2.2)

## Key Question 1: Which Wan-derived techniques give the largest speed or quality wins, and what did it cost to train them (GPU count, hours, data)?

### Takeaway
The largest end-to-end wins come from stacking a few-step distillation (DMD/Self-Forcing/rCM/Phased-DMD, 50→3-4 steps, ~15-50× by itself) with sparse or quantized attention (VSA, SLA, SageAttention; 1.5-6× on attention) and low-precision weights (FP8/NVFP4), giving 50-200× end-to-end on a single GPU; the documented training cost of the distillation stage is small — 1.5-16 h on 64 H100/H200 for a 1.3B model and ~12-52 h on 64 H200 for 5B/14B — and is usually data-free (prompts only). Training-free caches (TeaCache/EasyCache/MagCache) give a further ~1.5-2.6× on the undistilled model at measurable PSNR cost.

### Cited Findings

**A. Step distillation (training required)**

- *FastWan / Sparse-Distill (FastVideo, hao-ai-lab)*: FastWan2.1-T2V-1.3B-Diffusers is fine-tuned from Wan-AI/Wan2.1-T2V-1.3B-Diffusers with a "Sparse-distill" strategy that "jointly integrates DMD and VSA in a single training process"; trained on the FastVideo 480P Synthetic Wan dataset (FastVideo/Wan-Syn_77x448x832_600k, ~600k synthetic latents) on "4 nodes with 32 H200 GPUs", global batch 64, grad-accum 2, LR 1e-5, VSA sparsity 0.8, "4,000 steps (about 12 hours)"; 3-step inference, 61×448×832, "up to 16 FPS with 3-step inference on a single H100"; Apache-2.0; code github.com/hao-ai-lab/FastVideo; VSA paper arXiv 2505.13389 — [HF model card](https://huggingface.co/FastVideo/FastWan2.1-T2V-1.3B-Diffusers). The FastVideo docs give the same recipe but the slurm script comment says 8 nodes/64 GPUs, so the 1.3B GPU count is inconsistent between text and script — [FastVideo DMD docs](https://haoailab.com/FastVideo/distillation/dmd/)
- FastWan2.1-T2V-14B-Diffusers (480P): fine-tuned from Wan2.1-T2V-14B-Diffusers with sparse-distill on the same 600k synthetic latents; "8 nodes with 64 H200 GPUs", global batch 64, HSDP_shard_dim 8, sequence_parallel_size 4, LR 1e-5, VSA sparsity 0.9, "3,000 steps, about 52 hours"; claims "up to 50x faster denoising at 480P and 70x at 720P, on a single H100, with 3-step inference"; Apache-2.0 — [HF model card](https://huggingface.co/FastVideo/FastWan2.1-T2V-14B-Diffusers). The FastVideo docs page instead claims "up to 60x denoising-loop speedup at 480P and 90x at 720P" for the same model — [FastVideo DMD docs](https://haoailab.com/FastVideo/distillation/dmd/) (conflict: 50×/70× vs 60×/90×).
- FastWan2.2-TI2V-5B-FullAttn-Diffusers: "trained using only DMD" (no VSA), data-free ("The generator is trained with a simulated forward pass"), "about 12 hours on 8 nodes with 64 H200 GPUs", global batch 64, 3,000 steps, LR 2e-5, trained at 121×704×1280, 3-step inference; Apache-2.0 — [HF model card](https://huggingface.co/FastVideo/FastWan2.2-TI2V-5B-FullAttn-Diffusers); the docs list "up to 50x denoising-loop speedup at 720P" — [FastVideo DMD docs](https://haoailab.com/FastVideo/distillation/dmd/)
- FastVideo DMD guidance detail: `real_score_guidance_scale` default 3.5 "corresponds to 4.5 in standard CFG form" (subtract 1 when porting from Ho & Salimans-style papers); docs also link an "Attn-QAT" recipe (fine-tune with fake-quantized attention, then distill to timesteps [1000, 757, 522]) — [FastVideo DMD docs](https://haoailab.com/FastVideo/distillation/dmd/)
- *DMD2* (the base algorithm used by FastVideo/CausVid/Self-Forcing; arXiv 2405.14867): removes DMD's regression loss ("eliminate the regression loss and the need for expensive dataset construction"), adds a two-time-scale update, a GAN loss and multi-step sampling; one-step FID 1.28 on ImageNet-64 and 8.35 zero-shot COCO 2014 — [arXiv 2405.14867](https://arxiv.org/abs/2405.14867)
- *CausVid* (arXiv 2412.07772): "distilling 50-step diffusion model into a 4-step generator" via DMD, causal student initialised from teacher ODE trajectories, bidirectional teacher supervising causal student; 9.4 FPS on a single GPU with KV caching; VBench-Long total 84.27; base model, GPU type and training compute not stated in the abstract — [arXiv 2412.07772](https://arxiv.org/abs/2412.07772)
- *Self-Forcing* (arXiv 2506.08009, NeurIPS 2025 Spotlight): base Wan2.1-T2V-1.3B; init by fine-tuning with causal attention on "16k ODE solution pairs sampled from the base model" (following CausVid); prompts from a filtered LLM-extended VidProM; 4-step; "Each DMD experiment converges in about 1.5 hours on 64 H100 GPUs"; data-free for DMD/SiD variants; GAN variant used 70k videos generated by the 14B model; on one H100: chunk-wise 17.0 FPS / 0.69 s latency / VBench 84.31 (Q 85.07, S 81.28) vs Wan2.1 0.78 FPS / 103 s / 84.26, CausVid 17.0 FPS / 81.20, SkyReels-V2 0.49 FPS / 82.67, MAGI-1 4.5B 0.19 FPS / 79.18; frame-wise 8.9 FPS / 0.45 s / 84.26 — [arXiv HTML 2506.08009](https://arxiv.org/html/2506.08009). GitHub README: "600 iterations, under 2 hours on 64 H100 GPUs", authors estimate reproduction "in under 16 hours on 8 H100s" with gradient accumulation; checkpoints gdhe17/Self-Forcing (self_forcing_dmd.pt, ode_init.pt); Apache-2.0; ODE-init instructions "still pending" — [GitHub guandeh17/Self-Forcing](https://github.com/guandeh17/Self-Forcing)
- *lightx2v Wan2.1 StepDistill-CfgDistill (4-step, 14B)*: "4 steps" "without classifier-free guidance"; training code "adapted from the Self-Forcing repository" and "extended to Wan2.1-14B-T2V" as a "4-step bidirectional distillation process"; no training data, GPU or eval numbers on the card; Apache-2.0 — [HF lightx2v/Wan2.1-T2V-14B-StepDistill-CfgDistill](https://huggingface.co/lightx2v/Wan2.1-T2V-14B-StepDistill-CfgDistill). - *lightx2v Wan2.1-T2V-14B-CausVid* (autoregressive distill): built on CausVid code published as "CausVid-Plus", "9-step distillation", extended with "a training dataset of 50,000 prompt-video pairs"; lightx2v's own docs say the result is "mediocre" and "the acceleration improvement has not met expectations"; T2V only — [lightx2v autoregressive distill docs](https://lightx2v-en.readthedocs.io/en/latest/method_tutorials/autoregressive_distill.html); [search summary incl. HF lightx2v/Wan2.1-T2V-14B-CausVid](https://huggingface.co/lightx2v/Wan2.1-T2V-14B-CausVid)
- *Wan2.2-Lightning (lightx2v)*: T2V-A14B-NFE4-V1 Aug 4, 2025; I2V-A14B-NFE4-V1 and T2V V1.1 Aug 7, 2025; ComfyUI workflows Aug 8, 2025; T2V-A14B-NFE4-0928 (folder "250928", V2.0 preview "with better camera controllability and motion dynamics") Sep 28, 2025; T2V-A14B-NFE4-V2.0 Nov 8, 2025; TI2V-5B-4steps still a to-do; "only 4 steps and no CFG trick" giving "about a 20x speed-up"; method since Sep 28 credited to "Phased DMD"; no training/reproduction steps in the repo; Apache-2.0; eval prompts from Movie Gen Bench (CC BY-NC 4.0) enhanced with Qwen2.5-14B-Instruct — [GitHub ModelTC/Wan2.2-Lightning](https://github.com/ModelTC/Wan2.2-Lightning). HF card: LoRA rank 64 ("Wan2.2-T2V-A14B-4steps-lora-rank64-Seko-V1"), "Visuals on par with the base model in most scenarios, sometimes better", known limitation "videos with extremely large motion may show artifacts, and vehicle direction may sometimes be reversed"; single-GPU needs ≥80 GB VRAM — [HF lightx2v/Wan2.2-Lightning](https://huggingface.co/lightx2v/Wan2.2-Lightning)
- *Phased DMD* (arXiv 2510.27684, CVPR 2026) — the method behind Wan2.2-Lightning v2: splits the SNR range into sub-intervals, distils each Wan2.2 expert into a phase expert ("In the first phase, only the low-SNR expert is activated", then frozen while the high-SNR expert trains); generator trained as LoRA rank 64 / alpha 8 at LR 5e-5, fake score model fully fine-tuned at 4e-7; 4 steps in 2 phases, Wan2.2 timesteps 1000/938/833/625; "64 GPUs with PyTorch FSDP, gradient checkpointing, and context parallelism", batch 64, data-free; no total GPU-hours; results on 220 prompts: T2V optical flow 9.30 vs DMD2 3.23 (base 10.26), dynamic degree 82.27% vs 65.45%, FID 47.24 vs 55.70, FVD 700.9 vs 763.1; I2V FVD 334.7 vs 370.0; motivation: stochastic gradient truncation "slows motion dynamics in video generation" — [arXiv HTML 2510.27684v3](https://arxiv.org/html/2510.27684v3); [search result](https://arxiv.org/html/2510.27684v1)
- *lightx2v Wan2.2-Distill-Models / -Loras*: full 14B 4-step DiTs (BF16 ~28.6 GB, FP8 ~15 GB, INT8 ~15 GB) for I2V and T2V high/low noise; Apr 12, 2026 "Wan2.2-I2V-A14B-4step-720p-high/low" (tag 260412) "trained on a high-quality 720p dataset"; no benchmarks; Apache-2.0 — [HF lightx2v/Wan2.2-Distill-Models](https://huggingface.co/lightx2v/Wan2.2-Distill-Models); LoRA repo: rank-64 I2V high/low noise files e.g. `wan2.2_i2v_A14b_high_noise_lora_rank64_lightx2v_4step_1022.safetensors` (~635 MB) — [HF lightx2v/Wan2.2-Distill-Loras](https://huggingface.co/lightx2v/Wan2.2-Distill-Loras). **Weights-only beyond the Phased-DMD paper.**
- *rCM / TurboDiffusion (thu-ml + NVIDIA)*: rCM (arXiv 2510.08431, ICLR 2026) = sCM continuous-time consistency + score distillation as "long-skip regularizer" (forward + reverse divergence), FlashAttention-2 JVP kernel to train at >10B; distils Cosmos-Predict2 and Wan2.1 "up to 14B parameters", 1-4 steps, "about 15x to 50x" sampling speedup, "generally matches the state-of-the-art distillation method DMD2 on quality metrics" with less mode collapse — [arXiv 2510.08431](https://arxiv.org/abs/2510.08431). Repo: teacher Wan2.1 T2V (1.3B and 14B configs), synthetic data = Wan2.1-14B-generated videos (`worstcoder/Wan_datasets`, dir name suggests ~250K samples at 480p 16:9) from the Self-Forcing VidProM prompt file; recommended schedule "dCM (warmup) -> sCM -> DMD (+sCM)"; single-node example 8 GPUs, GPU-hours not stated; caveats "Few-step distilled models lag behind the teacher in aspects such as physical consistency" and "sCM + DMD joint training may be unstable for some models"; Causal-rCM arXiv 2606.25473; Apache-2.0 — [GitHub NVlabs/rcm](https://github.com/NVlabs/rcm). TurboDiffusion (arXiv 2512.16093) = rCM + SLA sparse-linear attention (arXiv 2509.24006) + SageAttention/quantized linears; on one RTX 5090 (E2E excl. text enc/VAE): Wan2.1 T2V 1.3B 480p 184 s → 1.9 s; 14B 480p 1676 s → 9.9 s; 14B 720p 4767 s → 24 s; Wan2.2 I2V A14B 720p 4549 s → 38 s ("100 ~ 200×"); checkpoints TurboDiffusion/TurboWan2.1-T2V-1.3B-480P, -14B-480P, -14B-720P, TurboWan2.2-I2V-A14B-720P; training code "partially available" (rCM-based, FSDP2 + Ulysses CP), "Organize and release training code" still open; trained "only on long English prompts"; Apache-2.0 — [GitHub thu-ml/TurboDiffusion](https://github.com/thu-ml/TurboDiffusion)

**B. Sparse / quantized attention**

- *VSA (Video Sparse Attention, arXiv 2505.13389)*: trainable sparse attention; "cuts training FLOPs by 2.53x with no drop in diffusion loss" in from-scratch DiT scaling 60M-1.4B; retrofitted on Wan-2.1 "attention time drops by 6x, and end-to-end generation time falls from 31s to 18s" with "comparable" quality; kernel "sustains 85% of FlashAttention3 MFU" — [arXiv 2505.13389](https://arxiv.org/abs/2505.13389)
- *Sparse VideoGen (SVG, arXiv 2502.01776, ICML 2025) / SVG2 (arXiv 2505.18875, NeurIPS 2025 Spotlight) / SVG-EAR (arXiv 2603.08982)*: training-free; "HunyuanVideo, Wan 2.1 and Cosmos can be accelerated by 2×" (SVG2); Wan2.1 T2V and I2V scripts; SVG1 open-sourced 2025/03, SVG2 2025/09; Apache-2.0; no PSNR numbers on the README — [GitHub svg-project/Sparse-VideoGen](https://github.com/svg-project/Sparse-VideoGen)
- *Radial Attention (arXiv 2506.19852, NeurIPS 2025)*: O(n log n) static mask with spatial locality and temporal decay; "Wan2.1-14B: 1.8× speedup at default video length" with quality "nearly identical"; the headline 3.7× is for HunyuanVideo at 4× length (500 frames 720p), not Wan; LoRA tuning lets models reach 4× longer videos at "up to 4.4×" (overview) / "4.6×" (performance section) lower tuning cost, no GPU counts given; released LoRA checkpoints for longer video still an unchecked to-do; open-sourced 2025-06-24; Apache-2.0 — [GitHub mit-han-lab/radial-attention](https://github.com/mit-han-lab/radial-attention)
- *SpargeAttn (arXiv 2502.18137, ICML 2025)*: "universal training-free sparse attention"; `topk` knob (example 0.5); no-tuning usage added 2025-05; SageAttention2++-based variant 2025-06; SpargeAttention2 (arXiv 2602.13515) is trainable with "hybrid top-k and top-p masking with distillation fine-tuning"; no Wan-specific numbers on the README; Apache-2.0 — [GitHub thu-ml/SpargeAttn](https://github.com/thu-ml/SpargeAttn)
- *SageAttention 1/2/2++/3* (arXiv 2410.02367 / 2411.10958 / 2505.21136 / 2505.11594): quantized attention "speedup of 2-5x compared to FlashAttention"; RTX 5090 note "560T and 2.7x faster than FlashAttention2"; SageAttention3 (Blackwell "Microscaling FP4 Attention") code released 2025-09-27; README's only end-to-end example is CogVideoX1.5-5B on H20 (FA2 25'34" → SageAttention 12'07"); no Wan numbers on the README; Apache-2.0 — [GitHub thu-ml/SageAttention](https://github.com/thu-ml/SageAttention)

**C. Training-free caching**

- *TeaCache (arXiv 2411.19108, CVPR 2025 Highlight)*: Wan2.1 support 2025/03/05, optimised 2025/03/13; on one A800: T2V 1.3B 832×480 ~175 s → ~88 s at thresh 0.08; T2V 14B 1280×720 ~55 min → ~27 min at 0.20; I2V 480P ~735 s → ~300 s at 0.26; I2V 720P ~29 min → ~12 min at 0.30; with `--use_ret_steps` 14B T2V ~578 s at 0.20; "about 2x without much visual quality degradation"; no quantitative quality metrics on the Wan page; Apache-2.0 — [TeaCache4Wan2.1 README](https://github.com/ali-vilab/TeaCache/blob/main/TeaCache4Wan2.1/README.md); [TeaCache main](https://github.com/ali-vilab/TeaCache)
- *EasyCache (arXiv 2507.02860, Jul 2025)*: runtime-adaptive, no offline profiling; on A800 with VBench prompts, Wan2.1-1.3B baseline 175.35 s; TeaCache 87.77 s (2.00×, PSNR 22.57, SSIM 0.8057, LPIPS 0.1277); EasyCache 69.11 s (2.54×, PSNR 25.24, SSIM 0.8337, LPIPS 0.0952); Wan2.1-14B demo labelled 2.63× vs TeaCache 1.46×; SVG+EasyCache on HunyuanVideo 720p (H20) 3.33× at PSNR 27.26 vs SVG+TeaCache 3.18× at PSNR 22.65; Apache-2.0 — [GitHub H-EmbodVis/EasyCache](https://github.com/H-EmbodVis/EasyCache)
- *MagCache (arXiv 2506.09045, NeurIPS 2025)*: magnitude-ratio criterion; released 2025/6/10; "1.5-2x speedup for Wan2.2 (2025/8/7)"; supports Wan2.1 T2V/I2V and VACE; no Wan2.1 numeric speedup or PSNR on README; Apache-2.0 — [GitHub Zehong-Ma/MagCache](https://github.com/Zehong-Ma/MagCache)
- *TaylorSeer (arXiv 2503.06923, ICCV 2025)*: Taylor-expansion feature forecasting; Wan2.1 support released 2025/03/30 with multi-GPU, no Wan speedup numbers (HunyuanVideo 5.00× compression / 4.65× latency); **GPL-3.0** (licence caveat) — [GitHub Shenyi-Z/TaylorSeer](https://github.com/Shenyi-Z/TaylorSeer)

**D. Quantization / low precision**

- LongLive INT8: 1.4 GB vs 2.7 GB BF16, 16.4 vs 12.6 FPS on RTX 5090, VBench 84.31 vs 84.87 — [arXiv HTML 2509.22622](https://arxiv.org/html/2509.22622)
- *Nunchaku / SVDQuant (arXiv 2411.05007)*: README and HF org (13 of 20 repos visible) list only image models (FLUX, Qwen-Image, SANA, Z-Image); no Wan repo found — [GitHub nunchaku-tech/nunchaku](https://github.com/nunchaku-tech/nunchaku); [HF nunchaku-ai](https://huggingface.co/nunchaku-ai)

**E. Pruning**

- *MobileWan (Qualcomm, arXiv 2607.06173)*: adapts Wan2.2-5B to phones with recurrence distillation (chunk-wise AR with constant-memory causal linear attention), learnable per-head attention-head pruning with "noise-biased sparsity objective and distillation-based finetuning", step distillation and memory-optimised VAE; 5 s 480×832 16 FPS in "about 20 seconds end-to-end latency", VBench 83.79; DiT checkpoint and sampling code via project page; reports that Neodragon-style block pruning "hurt Wan2.2 5B badly" (model "highly intolerant to this type of compression") — [arXiv 2607.06173](https://arxiv.org/abs/2607.06173); [search summary](https://arxiv.org/pdf/2607.06173)

### Inferences
- The distillation stage itself is cheap relative to pretraining: every documented Wan distillation (Self-Forcing 1.5-2 h × 64 H100; FastWan 1.3B 12 h × 32 H200; FastWan 5B 12 h × 64 H200; FastWan 14B 52 h × 64 H200; Self-Forcing-Plus 14B <3 days × 64 H100; Phased DMD 64 GPUs; LongLive 12 h × 64 H100) fits in roughly 100-3,500 GPU-hours. The cost driver at 14B is memory (four 14B copies for DMD: real score, fake score, student, EMA — see Krea notes under Q4), not data.
- Reported single-GPU end-to-end gains stack roughly multiplicatively: ~12-20× from 4-step/no-CFG distillation, ~1.5-3.5× from sparse/quantized attention, ~1.5-2× from FP8/NVFP4 weights, which is consistent with TurboDiffusion's 97-199× and lightx2v's "over 50×" claims.
- Caches are the only wins that require no training, but they are the only ones with published PSNR degradation (TeaCache PSNR 22.6 on Wan2.1-1.3B at 2×) and cannot be combined with 3-4-step students meaningfully.

### Gaps
- No source reports a VBench score for FastWan models; the FastWan blog at hao-ai-lab.github.io/haoailab.com returned 404 on 2026-10-21, so denoising-time-per-frame and the original FastWan release date could not be confirmed.
- SageAttention, SpargeAttn and MagCache READMEs give no Wan-specific speedup numbers.
- No GPU-hour totals are published for rCM/TurboDiffusion, Wan2.2-Lightning or Phased DMD.
- No depth/block-pruning paper targeting Wan2.1 was found; MobileWan is the only pruning work on a Wan model (head pruning of Wan2.2-5B).

## Key Question 2: Which published models were bootstrapped from Wan 2.1/2.2 weights into something new (audio-visual, long-form, streaming, world model), and how was that done?

### Takeaway
Wan has been bootstrapped in three ways: (a) full-weight initialisation plus new conditioning towers (Wan-S2V, Wan-Animate, InfiniteTalk, VACE, Wan-Fun, Phantom, Uni3C, Ovi's video tower), (b) conversion of the bidirectional model to a causal/streaming student via ODE-init + DMD (CausVid, Self-Forcing, LongLive, Krea Realtime 14B, StreamDiffusionV2/CausVid-Plus), and (c) reuse of only the Wan VAE + umT5 text encoder with a DiT trained from scratch (SkyReels-V2, HuMo). MAGI-1 is not Wan-derived.

### Cited Findings

**Streaming / long-form (causal conversion of Wan weights)**
- *Self-Forcing*: converts Wan2.1-T2V-1.3B to a 4-step causal AR model with rolling KV cache; data-free; chunks of 3 latent frames — [arXiv HTML 2506.08009](https://arxiv.org/html/2506.08009)
- *LongLive (NVlabs, arXiv 2509.22622)*: "frame-level autoregressive (AR) framework"; fine-tunes "a 1.3B-parameter short-clip model" (Wan2.1, building on Self-Forcing code) to a minute-long generator with KV-recache for prompt switches, streaming long tuning, and short-window attention with a frame-level attention sink; "32 GPU-days" = "about 12 hours on 64 H100 GPUs", 3,000 iterations at global batch 64 for the 60 s setting; teacher Wan2.1-T2V-14B; no real video data (VidProM prompts; switch prompts from Qwen2-72B-Instruct); 20.7 FPS on one H100, up to 240 s videos; VBench short 84.87 (Q 86.97, S 76.47); VBench-Long 30 s 83.52 vs Self-Forcing 81.59, FramePack 81.95, SkyReels-V2 75.29; LoRA needs rank 256 (~27% of params) for strong long-range quality; released 2025.09.29 with "all training and inference code"; checkpoint Efficient-Large-Model/LongLive-1.3B; Apache-2.0 — [arXiv HTML 2509.22622](https://arxiv.org/html/2509.22622); [GitHub NVlabs/LongLive](https://github.com/NVlabs/LongLive); [arXiv abs](https://arxiv.org/abs/2509.22622)
- *Self-Forcing++ (arXiv 2510.02283, Oct 2, 2025)*: extends AR students to "up to 4 minutes 15 seconds" ("99.9% of the maximum span supported by the base model's position embedding"), "20x beyond the teacher's capability", "50x longer than the baseline", by guiding the student with sampled segments of its own long self-generated videos, no long-video teacher or long-video data; compute unspecified in abstract — [arXiv 2510.02283](https://arxiv.org/abs/2510.02283)

## Key Question 4: What are the main failure modes or quality ceilings reported for distilled or streaming Wan variants?

### Takeaway
Reported failure modes cluster into: error accumulation / drift beyond the training horizon in AR students, loss of diversity and motion (mode-seeking reverse-KL in DMD; gradient truncation), first-frame distribution shift, colour shift in long audio-driven generation, physics inconsistency in few-step students, prompt-length sensitivity, and the hard ceiling that self-supervised distillation cannot exceed the teacher.

### Cited Findings
- Self-Forcing: "quality degradation remains observable when generating videos substantially longer than those seen during training"; gradient truncation "may limit the model's ability to learn long-range dependencies" — [arXiv HTML 2506.08009](https://arxiv.org/html/2506.08009); works better with long detailed prompts; TAEHV-VAE / FP8 linear speedups "may reduce quality" — [GitHub Self-Forcing](https://github.com/guandeh17/Self-Forcing)
- LongLive: performance "bounded by the capacity and quality of that base model"; short-clip quality "unlikely to exceed the base model's"; semantic score (76.47) trails Self-Forcing chunk-wise (81.28) and Wan2.1 (80.09); LoRA needs rank 256 — [arXiv HTML 2509.22622](https://arxiv.org/html/2509.22622)
- Krea Realtime 14B: error accumulation "worsens with longer context"; first-frame artifacts from different latent statistics on eviction; "repetitive motion" in long single-prompt runs; "mode collapse: the reverse KL term in DMD suppresses low-probability modes"; "struggles with complex camera movement" (earlier checkpoints had more dynamic camera but "many visual artifacts"); simple captions "give static output"; KV-recompute O(S²·N(N+1)/2) vs O(S²N) and Flex Attention overhead; T2V "the hardest task", V2V easier — [Krea blog](https://www.krea.ai/blog/krea-realtime-14b)
- Phased DMD / stochastic gradient truncation "slows motion dynamics in video generation"; DMD2 on Wan2.2-T2V dynamic degree 65.45% vs base ~ (Phased 82.27%), optical flow 3.23 vs base 10.26 — [arXiv HTML 2510.27684v3](https://arxiv.org/html/2510.27684v3)
- Wan2.2-Lightning: "videos with extremely large motion may show artifacts, and vehicle direction may sometimes be reversed" — [HF lightx2v/Wan2.2-Lightning](https://huggingface.co/lightx2v/Wan2.2-Lightning)
- rCM: "Few-step distilled models lag behind the teacher in aspects such as physical consistency"; "sCM + DMD joint training may be unstable for some models" — [GitHub NVlabs/rcm](https://github.com/NVlabs/rcm); TurboDiffusion trained "only on long English prompts" — [GitHub TurboDiffusion](https://github.com/thu-ml/TurboDiffusion)
- lightx2v CausVid-Plus AR distill: "mediocre" effect, speedup "has not met expectations" — [lightx2v docs](https://lightx2v-en.readthedocs.io/en/latest/method_tutorials/autoregressive_distill.html)
- SkyReels-V2: "the diffusion-forcing framework remains subject to error accumulation over extended generations" — [arXiv HTML 2504.13074](https://arxiv.org/html/2504.13074)
- InfiniteTalk: beyond ~1 min "colour shift becomes more pronounced"; FusionX LoRA worsens it — [GitHub InfiniteTalk](https://github.com/MeiGen-AI/InfiniteTalk)
- HuMo: longer than 97 frames "may degrade"; 1.7B lower visual quality than 17B — [GitHub HuMo](https://github.com/Phantom-video/HuMo)
- FastWan: trained at one resolution (61×448×832 or 121×704×1280); other resolutions "may degrade in quality" — [FastVideo DMD docs](https://haoailab.com/FastVideo/distillation/dmd/); [HF 5B card](https://huggingface.co/FastVideo/FastWan2.2-TI2V-5B-FullAttn-Diffusers)
- Caching quality cost: TeaCache on Wan2.1-1.3B PSNR 22.57 / LPIPS 0.1277 at 2.00×; EasyCache PSNR 25.24 / LPIPS 0.0952 at 2.54× — [GitHub EasyCache](https://github.com/H-EmbodVis/EasyCache)
- Pruning: Wan2.2-5B "highly intolerant" to block pruning — [MobileWan search summary](https://arxiv.org/pdf/2607.06173)
- VBench caveat: Phased DMD authors say VBench (other than dynamic degree) ranks the base model lowest, "which conflicts with human assessment" — [arXiv HTML 2510.27684v3](https://arxiv.org/html/2510.27684v3)

### Inferences
- The VBench totals of all 1.3B streaming students (84.26-84.87) sit within ~0.6 points of the Wan2.1-1.3B teacher (84.26), consistent with the "cannot exceed teacher" ceiling; the differentiation is in long-horizon stability and semantic score, not peak quality.
- Motion/diversity loss is the dominant quality regression of DMD-style distillation and is the explicit target of the newest recipes (Phased DMD, rCM's forward divergence, Krea's attention bias).

### Gaps
- No source quantifies error accumulation as a function of generated length for the 14B causal models (Krea gives qualitative description only).
- Self-Forcing++ failure-mode analysis (over-exposure, error accumulation) not retrievable (full text fetch failed).

## Key Question 5: Is there a published "recipe" a small team with a handful of 8-GPU nodes could follow to produce a competitive Wan derivative?

### Takeaway
Yes — at 1.3B/5B scale several fully documented, data-free recipes fit inside 1-4 nodes of 8×H100/H200 within hours to a few days (Self-Forcing: 64 H100 × ~1.5-2 h or "under 16 hours on 8 H100s"; FastWan2.2-5B DMD: 64 H200 × 12 h; LongLive: 64 H100 × 12 h; FastWan2.1-1.3B sparse-distill: 32 H200 × 12 h); at 14B the same recipes are documented at 64 H100/H200 for 12 h-3 days and are memory-bound (four 14B copies), with Krea reporting OOM on 64 H100 without custom memory work.

### Cited Findings
- Self-Forcing: "600 iterations, under 2 hours on 64 H100 GPUs"; "the authors estimate reproduction in under 16 hours on 8 H100s" — [GitHub guandeh17/Self-Forcing](https://github.com/guandeh17/Self-Forcing); "Each DMD experiment converges in about 1.5 hours on 64 H100 GPUs"; data-free; init from 16k ODE pairs — [arXiv HTML 2506.08009](https://arxiv.org/html/2506.08009)
- LongLive: "about 12 hours on 64 H100 GPUs", 3,000 iterations, batch 64, prompts only, teacher Wan2.1-T2V-14B, full training code — [arXiv HTML 2509.22622](https://arxiv.org/html/2509.22622); [GitHub NVlabs/LongLive](https://github.com/NVlabs/LongLive)
- FastVideo recipes (slurm scripts, hyperparameters): 1.3B 32 H200 × ~12 h (4,000 steps); 14B 64 H200 × ~52 h (3,000 steps, seq-parallel 4, HSDP shard 8); 5B 64 H200 × ~12 h (3,000 steps, data-free) — [FastVideo DMD docs](https://haoailab.com/FastVideo/distillation/dmd/)
- Self-Forcing-Plus (14B bidirectional 4-step, the lightx2v-style LoRA pipeline): T2V 3,000 iterations "under 3 days on 64 H100s"; I2V 1,000 iterations "under 12 hours on 64 H100s" — [GitHub GoatWu/Self-Forcing-Plus](https://github.com/GoatWu/Self-Forcing-Plus)
- Phased DMD (Wan2.2-28B MoE, LoRA rank 64 generator, full fake-score model): "64 GPUs with PyTorch FSDP, gradient checkpointing, and context parallelism", batch 64, data-free — [arXiv HTML 2510.27684v3](https://arxiv.org/html/2510.27684v3)
- rCM: single-node 8-GPU example command, staged schedule dCM → sCM → DMD(+sCM), teacher + synthetic 480p dataset hosted on HF — [GitHub NVlabs/rcm](https://github.com/NVlabs/rcm)
- Krea 14B causal: causal ODE pretraining "3k steps on 128 H100 GPUs"; Self-Forcing DMD at 14B OOMs "even with FSDP across 64 H100s" without dynamic KV-cache freeing via backward hooks, gradient checkpointing and ZeRO-3; KV cache ~25 GB/GPU — [Krea blog](https://www.krea.ai/blog/krea-realtime-14b)
- Wan-S2V engineering: FSDP 8×80 GB per node, context parallel on 8 GPUs reduced iteration from ~100 s to ~12 s at 48 frames 1024×768 — [arXiv HTML 2508.18621](https://arxiv.org/html/2508.18621)
- Wan-Fun provides baseline/LoRA/control/reward-LoRA trainers for Wan2.1/2.2 (no hardware doc) — [GitHub aigc-apps/VideoX-Fun](https://github.com/aigc-apps/VideoX-Fun)
- Quantization-aware distillation recipe exists only as lightx2v weights (Wan-NVFP4) and FastVideo's Attn-QAT recipe note — [HF lightx2v/Wan-NVFP4](https://huggingface.co/lightx2v/Wan-NVFP4); [FastVideo DMD docs](https://haoailab.com/FastVideo/distillation/dmd/)

### Inferences
- A practical "small-team" path implied by the sources: (1) take a lightx2v/FastVideo 4-step bidirectional student or train one with Self-Forcing-Plus/FastVideo (1.3B: 1 node-day; 14B: ~8 node-days); (2) convert to causal with CausVid ODE-init + Self-Forcing DMD (1.3B: <1 node-day) and optionally LongLive streaming-long tuning (~4 node-days); (3) add training-free VSA/SageAttention/SLA and FP8/NVFP4 at inference. All of these are documented at 64-GPU scale, so a team with 2-4 nodes should expect 4-8× longer wall clock via gradient accumulation (Self-Forcing authors' own 8-H100 estimate is 16 h).
- 14B causal distillation is the only step with a reported hard blocker (OOM at 64 H100 in naive code) and has no public trainer (Krea released inference only), so a 14B streaming derivative requires re-implementing Krea's memory tricks or using Causal-rCM (arXiv 2606.25473, code in NVlabs/rcm).

### Gaps
