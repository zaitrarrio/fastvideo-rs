# Work orders: driver-only runtime, step 2 (ADR-0024)

Owner decision 2026-11-24, FVID-2026-11-24-drop-cudnn-sdpa (D2): drop cuDNN
from the attention path now, take the margin back with SageAttention2 on
sm_12x for the models whose quality gate allows it, and optimize
`flash_mma_fwd2` for every other case. Measurement behind it:
`docs/perf/2026-11-24-sdpa-rule-cudnn-margins.md`. Three increments:

| WO | what | state |
|---|---|---|
| 2a | the cuDNN candidate off `auto` | done in PR #252 |
| 2b | SageAttention2 gates per model on sm_12x | ready to run (GPU) |
| 2c | `flash_mma_fwd2` tuning for sm_12x | ready to plan; kernel work with GPU iteration |

What step 2 does **not** do: remove `cudnn_sdpa.rs` or the cuDNN library.
Both stay until step 3 replaces the convolutions (ADR-0024 says fv-gpucheck
and fv-lab may keep cuDNN as references); `FASTVIDEO_FLASH_KERNEL=cudnn`
stays a diagnostic override.

```
## WORK ORDER 2a: the cuDNN candidate off `auto` (done, PR #252)

### What changed
- `rt/sdpa_rule.rs`: `RULES` is empty, `CUDNN_DEFAULT_ON` is false. `pick`
  returns `flash_mma_fwd2` for every shape on every architecture;
  `cudnn_default()` is false everywhere. The identity oracle
  (`sdpa_rule_identity.rs`) reads the same constants, so rule and oracle
  stay equal. Unit test `no_shape_picks_cudnn_since_d2`.
- fv-gpucheck `sdpa_rule`: the check holds the rule to the faster of the
  kernels `auto` may pick (fwd2 alone: loss 0 by construction); the cuDNN
  margin is reported, not judged (`cudnn_margin_left` per row,
  `cudnn_faster_at` in the table note). `attn3_bench` unchanged: cuDNN is
  still measured as a reference.
- docs: ADR-0024 D2, `docs/perf/determinism.md` rule table, the decision log.

### What it changes for served outputs
On sm_12x, bf16-output dense attention with sq >= 24 576 and
24 576 <= sk <= 128 000 at d = 128 (H3 768p / 1080p dense blocks, LTX
1080p stage 2 and 20 s clips, Wan 720p self-attention) ran cuDNN's engine
11 and now runs fwd2. The two kernels round 1-2 bf16 ulp apart; in the
2026-09-27 A/B that moved H3 frames 20.4 dB PSNR and LTX frames 32.7 dB
(H3's known sensitivity, not a defect). Every other GPU, every cross
attention and every short shape is byte-identical. `ltx-pro` is unaffected
on its long shapes (Sage runs before the rule).

### Verification (GPU, pending)
- [x] `fv-gpucheck kernels --groups sdpa_rule` on an RTX PRO 6000 at
      `c041474` (pod `ppo6xqe5cn7lq8`, 1 min 40 s, runtime image
      `sha-c041474`): 19 of 19 `sdpa_rule_*` checks pass, every row picks
      `flash_mma_fwd2`, `cudnn_candidate` false, `cudnn_faster_at` lists the
      long self-attention shapes (H3 768p 3.5 %, H3 1080p 3.8 %, LTX 1080p
      20 s 3.9 %, Wan 720p 8.8 %; the short-shape entries are timer noise
      above the 50 us floor). Records:
      `artifacts/runpod/rtx6000/c041474-11242121/`.
- [ ] One `attn3` tier run (`fv-lab`, cell `attn3-h3-ltx25`): the `v2` and
      `cudnn` arms both still run (the override), the frame compare between
      them is the known 20 / 33 dB, and `auto` matches the `v2` arm byte for
      byte. About $3, 40 min.
- [ ] gold tier (ADR-0023): the records whose cells hit the rule's shapes
      (sol-h3, fasth3-*-dense, h3-* at 768p+, ltx25-* 1080p, wan*-720p) are
      re-run or annotated; a record's latency numbers move by the 3-5 %
      above and its quality fields by the bf16-ulp noise. Owner's call
```

```
## WORK ORDER 2c: `flash_mma_fwd2` tuning for sm_12x

### Objective
Close the 4-8 % kernel margin cuDNN had over `flash_mma_fwd2` on long
self-attention on RTX PRO 6000 (H3 768p 112.3 -> 107.2 ms, LTX 1080p 20 s
686 -> 658 ms, Wan 720p 24.7 -> 22.8 ms), for the models Sage does not
cover (H3 first), without changing fwd2's bytes where it is the parity
reference, or with a new kernel id beside it.

### What is known
- fwd2 (`rt/kernels/attn2.cu` `flash_mma_fwd2_d128`): mma.sync bf16, 128
  queries per CTA, 256 threads, `__launch_bounds__(256, 1)`, K/V tiles of
  FA_TILE rows double-buffered in 64 KB dynamic shared memory, online
  softmax in f32.
- fwd3 (S_{j+1} issued before softmax(S_j), three-stage K/V ring,
  branch-free tail) is bit-identical but 3 % slower: at 255 registers with
  spills ptxas keeps the softmax chain ahead of the QK HMMAs; fwd3s (skip
  the O rescale when no row max rose) recovers 0.5 %
  (docs/gaps/2026-09-27-attention-sm120-cudnn-vsa.md §2). So "more
  pipelining at the same tile" is spent.
- cuDNN engine 11 reaches 388-400 TFLOPS at H3 768p against fwd2's ~370;
  the sm_12x ceiling for bf16 mma.sync is not far above (SageAttention2's
  INT8 path gets 1.5-1.8x by changing the datatype, not the schedule).

### Candidate directions, in order of expected return
1. **Tile shape**: 64-query CTAs with `__launch_bounds__(128, 2)` (two
   CTAs per SM) or 128 queries x 2 KV tiles in flight; measure occupancy
   against register pressure with `FV_DC_PTXAS_VERBOSE=1`.
2. **Softmax arithmetic**: exp2 with the log2 scale folded into Q (the
   `sl2` argument already carries it), fewer f32 conversions on the P tile
   before the PV mma, bf16 P with f32 accumulate (what cuDNN and Sage do).
3. **Memory**: cp.async with L2 prefetch hints for the K/V stream; swizzled
   shared layouts to remove the ldmatrix bank conflicts the profile shows.
4. **Causal / masked variants** share the body: keep them on the old
   kernel until the dense one is proven.

### Acceptance criteria (executable)
- [ ] A new kernel id (`v4`) beside fwd2, selectable with
      `FASTVIDEO_FLASH_KERNEL=v4`; `auto` moves to it only by a rule row
      added with the measurement that justifies it (`sdpa_rule::RULES`,
      the `sdpa_rule` group as the offline tool).
- [ ] fv-gpucheck `attn3_parity`: v4 within 1 bf16 ulp of fwd2 on every
      parity shape (bit identity is not required: fwd2 stays the reference).
- [ ] fv-gpucheck `attn3_bench` on an RTX PRO 6000: v4 at least as fast as
      cuDNN engine 11 at H3 768p and LTX 1080p 20 s, and not slower than
      fwd2 at any benched shape.
- [ ] A generation A/B (the `attn3` cell, v2 vs v4 arms): H3 and LTX frames
      within the bf16-ulp band (PSNR >= the v2-vs-cuDNN numbers), denoise
      step time back to the cuDNN arm's or better.
- [ ] `task check`, `task nvrtc` green; the AOT tables carry v4 for every
      SM in FV_CUBIN_SMS.

### Budget
Iterative: each measurement round is a `kernels` run (~3 min, ~$0.15) plus
compile time on the build pod; expect 10-20 rounds, then one A/B (~$3).
A profile pass (`nsys-pod.sh`) at the start, ~$1.5.

### Decision points — STOP and ask
- v4 cannot reach fwd2's parity band at some shape.
- The best v4 still trails cuDNN at H3 768p by more than 2 %: the owner
  decides whether to keep the gap or revisit the H3 Sage gate.
```
