2 · How it works

Each fal model page mirrors a fal.ai model page: a Playground with the endpoint's input form, a result pane with the video, logs, timings, tier and recipe, and an API tab with cURL, Python and JavaScript snippets for the inputs you chose, on fal and on every other API this server mounts (native, OpenAI videos, MiniMax, LTX, Reactor).

Requests go through this server's fal queue API (POST /{app}/{task}, then status and result); attachments upload through /storage/upload/initiate. The Director page drives the live WebRTC session (clip or causal). Live stream runs a causal model (SF-Wan, LongLive) with prompt switches; Live input feeds a duplex model your camera; Native API submits /fv/v1/jobs with the fields only it takes, on any served model or tier, including tiers with no fal endpoint.
